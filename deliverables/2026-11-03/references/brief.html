첫 제품의 중심 약속

선택한 프로젝트 폴더에서 확인 가능한 소스 관계를 읽고, CLI가 작업할 때 모듈·노드의 변화와 작업 이유를 보여준다. Meta 설명과 근거를 구조화해 다음 CLI가 MCP로 프로젝트 문맥을 다시 활용하게 한다. 사용자의 편집기·터미널·파일 탐색기는 그대로 둔다.

CLI 작업 보고와 파일 감시를 함께 사용합니다. MCP 연결만으로 다른 도구의 모든 행동이 자동 전달되지는 않습니다. hooks가 없는 변경은 작업자를 추정하지 않고 관찰 범위만 표시합니다.

첫 구현에서 끝내야 할 범위

  1. 폴더 선택 / 드롭. 명시적으로 고른 한 프로젝트부터 읽는다. 탐색기에서 폴더에 들어간 사실을 자동 감지하는 기능은 별도의 OS 연동으로 구현·검증한다.
  2. 읽기 전용 분석. JavaScript / TypeScript의 import·export·호출 관계부터 시작한다. 다른 언어는 지원 수준을 표시하고, 해석하지 못한 의존성을 임의로 연결하지 않는다.
  3. 실제 투명한 데스크톱 창. 창 이동·크기 조절·상단 고정·불투명도 조절을 제공한다. 클릭 통과 모드는 단축키와 트레이 메뉴로 반드시 해제할 수 있어야 한다.
  4. 근거를 가진 그래프. 파일·함수·상태·데이터를 형태와 텍스트로 구분한다. 연결선은 종류·방향·파일·줄 번호를 함께 제공한다.
  5. 변경 감시. CLI나 에디터가 파일을 고치면 변경된 부분을 다시 분석한다. 기존 노드 위치를 유지하고 변경 배지만 표시한다.
  6. 실제 사용 검수. 다른 폴더 전환, 삭제·이름 변경, 분석 오류, 큰 폴더, DPI, 밝고 복잡한 배경, 클릭 통과 복구를 실제 데스크톱에서 검증한다.

투명함보다 중요한 가독성

배경은 비치고, 글자는 또렷하게

패널 배경에만 투명도를 적용합니다. 노드 이름과 선택 정보에는 독립된 대비 면을 둡니다. 시안의 65–75%는 탐색값이며 검증된 최적값이 아닙니다.

작업을 방해하지 않는 크기

평소에는 작은 고정 패널로 유지하고, 모듈을 펼칠 때 넓힙니다. 그래프를 보기 위해 에디터나 터미널 전체를 덮을 필요가 없어야 합니다.

큰 폴더는 단계적으로

처음에는 폴더·패키지 묶음을 표시합니다. 선택한 묶음의 내부를 펼치며, 모든 파일과 연결선을 한꺼번에 그리지 않습니다.

관계의 의미를 명시

import / calls / reads / tests를 구분합니다. 화살표는 관계 방향이며 실행 순서가 아닙니다. 변경 영향은 역방향 탐색하더라도 원래 화살표를 뒤집지 않습니다.

AI의 역할 · 사용자 요구 반영

관계 추출의 근거는 파서·컴파일러가 제공합니다. Meta AI는 모듈 요약, 작업의 의미, 설계·생성 이유, 대안과 제약, 초보자·중급자·숙련자 설명을 담당합니다. CLI가 밝힌 의도, 소스에서 확인한 사실, Meta의 해석을 구별하고 파일·심볼·해시를 근거로 연결합니다. 같은 기록에서 사람용 설명과 기계용 JSON 문맥을 제공합니다. 실제 소스가 바뀌면 이전 설명을 갱신 대기로 표시하며 현재 근거로 사용하지 않습니다. 새 Meta 연결·모델 검증은 아직 수행하지 않았으며 생성 시안은 Meta API 호출 결과가 아닙니다.
