# 실제 EXE 도킹·양방향 선택 화면 검수

사용자가 검수 창을 켰다고 알렸고 PID 22876의 `visual-review-2026-11-02T07-41-44-370Z/ready.json`을 확인했다. 이 턴에서는 열린 **실제 Electron EXE**를 제한된 검수 프로토콜로 조작했다. 이전의 IPC 차단만 확인한 상태와 다르다. 검수 창은 격리된 Checkout 복사본을 사용하며 종료하지 않고 기본 라이트 작업면으로 복원했다.

## 실제 화면에서 발견하고 수정한 문제

- 상단 기능 메뉴의 최소 폭이 없어 검색창 위로 겹쳤다. 메뉴 행을 별도로 확보하고 버튼이 축소되지 않게 했다.
- Source 근거 버튼과 비활성 설명 탭이 어두운 배경에서 검은 글씨로 표시됐다. 해당 패널의 실제 색 대비를 수정했다.
- 강조된 Apply coupon 버튼의 파란 배경이 강조 틴트로 덮여 흰 글씨가 사라졌다. 관련 버튼의 배경·글자 대비를 유지한다.
- 축소된 모듈 제목의 두 줄 clamp와 글꼴 높이 때문에 잘림 검사가 실패했다. 자연 줄바꿈과 글리프 여유 공간을 확보했다. 검사를 느슨하게 바꾸지 않았다.
- 초기 자동 선택만으로 프리뷰 대부분이 흐려졌다. 사용자의 첫 선택 전에는 전체 프리뷰가 보인다.
- 콘솔을 접어도 남은 분할의 `0.86fr` 때문에 아래에 빈 공간이 남았다. 남은 패널에 `1fr`를 배정해 공간을 회수했다.
- 작은 콘솔에서 로그 행이 반쯤 잘렸다. 짧은 패널에서는 입력줄만 보이고, 높이를 늘리면 실제 로그가 다시 보이도록 container query를 넣었다.
- 같은 URL을 reload했을 때 브라우저가 이전 CSS/JS를 재사용하는 것을 실제 캡처에서 확인했다. UI 자원 URL에 `?v=0.6.1-r4`를 넣었다. 최종 배포 UI는 **0.6.1**이다. 보조 브라우저 검사기의 bootstrap 삽입도 query가 있는 script URL을 처리하도록 수정했다.

## 검수 증거

- 원본: `artifacts/desktop/resources/artifacts/visual-review-2026-11-02T07-41-44-370Z/`.
- 최종 검수 계획: `artifacts/native-review-20261102/plan-c.json`. **34개 요청 모두 실제 새 프레임 PNG 생성, 글자/실루엣/패널 경계 검사 통과**. PNG 해시와 기록된 소스 13개 해시가 최종 파일과 일치한다. 요약은 같은 폴더 `report.json`이다.

## 검수의 한계

현재 결과는 Checkout의 선언 프리뷰와 위 화면 조작을 증명한다. 새 실제 Meta 호출·분리/통합 변경 적용·GLB·임의 프로젝트 자동 실행 UI 발견을 검증하지 않았다. 도킹의 프리셋·접힌 상태·최대화 표시를 확인했지만 이번 프로토콜로 **실제 탭 드래그나 구분선 포인터 이동을 실행한 것은 아니다**. 해당 상호작용의 기존 DOM 검사와 구분한다.

Route Atlas/Orbit은 전체를 맞출 때 28%로 축소되어 작은 이름을 읽으려면 확대가 필요하다. 작은 창에서는 모듈 전체 개요도 작아지고 프리뷰·긴 소스·설명은 독립 스크롤로 접근한다. 시각적 최종 사용자 승인이나 모든 기능 100% 완료로 확대하지 않는다. Unity/MR 폐기는 유지한다.
