# 역할별 모듈 몸체와 작업별 화면 구성

사용자는 프리뷰·모듈 영역의 색상 분리만으로는 차별성이 부족하다며 전체 구성을 다시 만들라고 요청했다. 이전 디자인은 승인되지 않았다. 이번 변경은 실제 Electron UI 0.5.0이며, 새 픽셀 검수가 끝난 상태는 아니다.

## 실제 구현

- `visual-model.js`가 실제 인덱스 종류와 직접 호출 수를 기준으로 몸체를 지정한다. 함수는 육각형, 두 개 이상 직접 호출하는 함수는 모서리를 자른 칩, 상태는 원통, 클래스는 폴더, 이미지는 사진 프레임, 뷰 요소는 창 프레임이다. `assembly.js`는 실제 SVG 경계를 렌더링한다. 색만 바꾼 직사각형을 사용하지 않는다. 원래 210×144 배치 좌표, 관계 ID, 두 연결 포트는 유지한다.
- 프리뷰와 모듈 작업면의 기존 폭 조절을 유지한다. 작업면 안에서 그래프와 하단 근거 영역을 나누고, `Source` / `Why this design` 탭으로 코드와 설명을 구분한다. 소스는 실제 선언 위치의 줄 번호와 안전한 텍스트 기반 구문 색을 표시한다. 복수 발췌도 각 선언의 실제 줄 번호를 사용한다. 설명 탭은 기존 수준 선택·Meta 분석·질문·AI 계약을 사용한다. 탭 전환과 확대는 프리뷰 root와 전체 구성을 바꾸지 않는다.
- 지도는 클래스 폴더 안에 실제 멤버 행을 표시한다. 모듈 이해 화면은 내부 구성과 근거 읽기를 나란히 배치한다. 관계 화면은 그래프 옆에 수학·가중치·영향을 유지한다. 분리·통합은 서로 다른 파일/프로젝트의 서류 묶음, 에셋은 큰 이미지 무대와 라이브러리, 검토는 전후 소스와 diff, 이력은 시간 순 기록으로 구성한다.
- 영어 기본, light/dark, 큰 프리뷰의 선언 바인딩, 전체 구성 ID, 실제 소스, 드롭과 기존 분리·통합·검토 기능을 보존한다. `visual-identity.css`가 최종 표현을 담당한다. Unity/MR을 복구하지 않는다.

이 모양은 소스의 구조적 종류를 설명한다. 비즈니스 중요도, 실제 실행 순서, Meta가 생성한 설계 근거라는 의미를 부여하지 않는다. 설명이 없을 때는 기존의 미생성/소스 기반 표시를 유지한다. 자동 런타임 프리뷰 발견이나 GLB 메시 생성을 추가한 작업이 아니다.

직접 시작한 PID 30732는 `artifacts/identity-native-20261102/stderr.log`의 **Mojo IPC Access denied (0x5)**로 종료됐다. 새 PNG가 없다. 기본 sandbox/권한/인증서 설정을 낮추지 않았다. 이전 27장은 이번 디자인의 성공 근거가 아니다.

사용자에게 일반 cmd에서 다음 검수 모드를 한 번 실행하고 켜 두도록 비동기로 요청했다. 현재 실행 응답과 `ready.json`은 없다.

```cmd
"C:\Users\dlfgu\Documents\GitHub\MetaAIHack\artifacts\desktop\Depth AI.exe" --visual-review
```

`visual-review.cjs`는 명시적 CLI 모드에서만 작동하며 Checkout 복사본과 별도 사용자 데이터를 사용한다. 정상 앱에는 외부 명령 수신기가 없다. 로컬 증거 폴더 `artifacts/desktop/resources/artifacts/visual-review-<시각>/`의 제한된 JSON 요청만 읽는다. 소켓·임의 JavaScript·셸 명령·소스 적용·Meta 호출을 허용하는 프로토콜이 아니다. 유효한 화면, 테마, 배치, 선언 바인딩, 모듈 선택, 탭, 제한된 창 크기/배율, UI 새로 고침과 캡처만 가능하다.

정상 시작 시 `ready.json`, 첫 `00-initial.png/json`을 생성한다. 다음 요청은 같은 폴더의 `request.json`에 고유 ID로 저장한다. 실제 Electron 포인터 입력과 hit test로 선택하며, 실패는 해당 JSON에 남긴다. UI만 배포 폴더로 갱신한 후 `reload:true`로 같은 창에서 재검수할 수 있다. 메인 프로세스 코드를 바꾸면 재시작이 필요하다.

```json
{"id":"01-total-guide","view":"feature","theme":"light","layout":"guide","previewKey":"total","evidence":"source","width":1600,"height":1000,"zoom":1,"reload":true}
```

각 PNG는 8px 새 프레임 표식과 해시, 실제 실행 소스 해시를 기록한다. `identity-audit.cjs`는 실제 도형 안에 글자가 들어가는지, 아이콘·역할·값과 제목이 겹치는지, 페이지 너비, 큰 창에서 그래프와 근거 영역이 함께 보이는지를 측정한다. `--smoke`의 최신 schema는 `desktop-identity-1`이며 기존 전체 흐름에도 이 측정과 설명 탭 캡처를 넣었다. 검수기 구현 완료와 실제 실행 통과는 다르다.

후속 작업은 사용자 실행의 `ready.json` 확인 → 큰 창의 모든 화면/세 배치/프리뷰 이미지·값·텍스트 → dark/light → 작은 창/125% → 실제 PNG 직접 검토와 수정이다. 시각적 완성·사용자 디자인 승인·모든 기능 100%를 주장하지 않는다.
