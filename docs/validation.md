# 초기 프로토타입 검증 기록

> 현재 상태는 [2026-10-30 인수인계](HANDOFF-2026-10-30.md)와 이 문서 마지막의 공유 영향 분석 검증을 기준으로 한다. 아래 기록은 각 시점의 결과이며 과거 미구현 목록을 최신 상태로 해석하지 않는다.

검증일: 2026-10-29 / Windows 11 / Unity 6000.3.13f1 / .NET SDK 8.0.419.

## 통과

- `.NET Release publish`: 경고 0, 오류 0.
- `--self-test`: 15개 assertion 통과. 공유 구현 단일화, partial 타입 복수 위치, 정적 관계 근거, 승인 거부, 경로 탈출 거부, 전체 snapshot 충돌 감지, 승인 코드 적용, revision 갱신, 본문 변경·파일 이동의 C# 심볼 ID 보존, 기능 분류 유지·만료, runtime snapshot 일치·만료를 검사.
- `python tests/integration.py`: 실제 로컬 HTTP 서버에서 인증·Origin 차단, C#와 Dart 혼합 가져오기, Dart analyzer 프로세스 실행, 검색·소스 조회, 외부 변경 재분석, runtime selection 만료 통과. 산출물: `artifacts/integration-result.json`.
- `dart analyze`: No issues found. 캐시에 설치된 analyzer 10.1.0을 사용.
- Unity Windows player: 배치 빌드 성공. 런타임 bridge의 Editor 코드도 컴파일 대상에 포함.
- Windows EXE 실행: 현재 **실제 저장소**를 가져와 index JSON 생성, 공간 지도·영역 목록·inspector 표시, 종료 확인. 샘플 그래프 주입 없음. 최종 산출물: `artifacts/windows/smoke.json`, `smoke.png`, `artifacts/player-visible.log`.

## 발견 후 수정한 문제

- 빌드에서 동적으로 참조한 Unlit shader가 제외됨 → Resources material로 포함.
- 비선택 runtime 응답의 빈 body → JSON `null`로 계약을 명확히 수정.
- 화면을 숨긴 Unity 실행에서 검은 캡처 → 실제 창 표시 + Direct3D 11에서 화면 검증. 숨김 실행 결과로 UI 성공을 주장하지 않음.
- Dart 클래스 이름 API deprecation → analyzer 10.1 API로 갱신.
- 긴 모듈 경로 카드 잘림 → 카드에는 짧은 이름, inspector에는 전체 이름 표시.

## 아직 검증하지 않은 항목

- 실제 Codex 계정/모델 호출로 생성한 제안의 품질 및 end-to-end 승인 수정. CLI 실행·JSON schema·검토 UI는 구현되어 있으나 이번 검증에서는 실제 모델을 호출하지 않음. 수정 적용 경계는 모델 없는 결정적 self-test로 검증.
- 실제 게임 프로젝트 Play Mode에서 캐릭터 클릭 후 컴포넌트 매핑. Editor 어댑터 컴파일과 서비스 관찰 계약만 검증.
- Flutter UI element 선택, 대상 Unity/Flutter 빌드 및 행동 보존 테스트.
- 수천 모듈의 성능, CPU·메모리 상한, 지속 작업 복구, 병렬 외부 편집의 모든 race condition.
- API key provider, Depth MCP server, 신규 소프트웨어 생성, 두 프로젝트 통합, MR 협업.
- 토큰 절감 또는 AI 정확성 향상. 이를 뒷받침할 비교 실험은 수행하지 않음.

전체 개발 플랫폼의 완성이 아니라, 실제 소스와 연결된 첫 실행 가능한 수직 단면입니다. 다음 우선순위는 대상 프로젝트 빌드 환경 로딩, 모듈 검색 기반 에이전트 문맥 제한, 실제 프로젝트에서 AI 변경과 검증을 연결하는 것입니다.


## 2026-10-30 — 선택 화면 수정과 실제 macOS 실행

- Unity 6000.3.13f1에서 macOS 앱 및 Windows EXE 빌드 성공. Windows 버전은 이번 세션에서 실행하지 않았다.
- .NET SDK 8.0.427로 macOS arm64 / Windows x64 서비스를 런타임 포함 publish. Roslyn 참조의 CS8012 아키텍처 경고 2건이 있었으며, macOS 서비스 실행·분석 테스트는 통과했다. SDK 9/10의 Roslyn을 net8.0에 직접 참조하면 실패하므로 macOS 빌드 스크립트에서 SDK 8을 검사한다.
- 서비스 self-test 28개 통과. `tests/native_workspace.py`의 실제 HTTP·stdio MCP 조회/변경 검토/적용/재분석 통과.
- 창을 표시한 실제 Unity macOS 앱에서 라이트 구성·할인 속성·다크·소스·변경 검토 화면 캡처. 가짜 카드 데이터나 HTML 렌더링을 사용하지 않았다.
- 격리된 `native-smoke-20261030` 복사본에서 할인 20 → 25, draft 합계 90, 승인 적용 후 합계 90 및 canonical ID 유지 확인. 저장소의 `samples/Checkout`은 변경하지 않았다. 증거: [실행 결과](screenshots/2026-10-30-native-proof.json).
- 상품/주문 요약 분리로 프리뷰 합계와 버튼 겹침 해결. 검사기는 선택한 선언의 속성만 표시하며, 관련 할인 속성은 별도 선택 버튼으로 이동한다.
- 구성판에는 실제 root ID와 직접 참조, closure 안의 프리뷰 할인 속성을 최대 5개 표시한다. 하단 탐색대는 실제 인덱스의 최대 40개를 가로 스크롤하고 전체 목록/검색으로 나머지에 접근한다. 코드 통합·복제나 의미적 모듈화 완료를 뜻하지 않는다.
- 기존 PNG 아이콘 연결. 아이콘 선택은 선언 종류와 이름 기반 표시 규칙이며, 분석으로 검증한 의미적 역할 분류가 아니다.
- [레퍼런스와 현재 실제 캡처 비교](visual-handoff.html). 배치·아이콘·간격은 개선했지만 레퍼런스의 입체 유리 재현은 여전히 미완료다. 표면은 UI Toolkit 절차적 메시·반사색·층으로 표현하며 실제 굴절/배경 블러는 없다. 전체 탐색의 기존 3D 표현과 하단 모듈 몸체의 공간감은 다음 수정 대상이다.
- 실제 모델 계정 호출, Windows 런타임, 일반 프로젝트 프리뷰는 이번에 검증하지 않았다. UI 클릭/스크롤 전체를 자동화한 테스트는 아니며, smoke는 앱 내부 화면 전환·서비스 호출과 실제 렌더링을 검증했다.


### 같은 날 추가 공간 수정

사용자가 기존 평면 결과와 임의의 선택 화면 상단 여백을 다시 거부했다. 상단 여백을 제거했고 선택 작업판은 오른쪽 전체, 프로젝트 탐색은 하단으로 유지한다.

DepthSpatialField를 지속적인 실제 ID 기반 3D 오브젝트로 교체했다. 최대 9개 몸체에 사선 회전·두께·다층 유리·GrabPass 굴절 shader·부유 움직임을 적용했다. 선택한 몸체만 전진하며 정면 회전하고, Explore에서 원래 위치·각도로 복귀한다. 나머지는 유지된다. 검색으로 표시 대상이 바뀔 때만 생성/제거한다. Reduce motion은 부유를 끄고 전환을 단축한다.

macOS 실제 앱 smoke에서 모듈 중심을 향한 Physics ray 선택 → 이동 중간 프레임 → 오른쪽 전체 구성판 → 코드 조회 → Explore 복귀를 실행·캡처했다. macOS와 Windows 빌드 성공; Windows 실행은 미검증. 이전 정면 공간 캡처 대신 추가 공간 캡처를 비교 페이지 맨 위에 보존했다. 이 검증은 모든 화면 좌표의 실제 OS 포인터 입력을 자동화한 검증은 아니다.

시각적 한계: 현재는 단순한 소스 선언 단위 몸체이며 레퍼런스의 정교한 기능 모듈 내부 구성과 광학 품질에는 차이가 남는다. 사용자 승인 또는 레퍼런스 재현 완료로 기록하지 않는다.


### 입력 처리 재수정 — 사용자 지적

사용자는 하단 드래그 부재, 하단 선택 애니메이션 부재, 모듈 전용 화면 진입 불명확, 버튼을 놓아도 마우스를 따라 움직이는 문제를 지적했다. 상단 Module space 진입점을 추가하고 Workspace로 돌아올 수 있게 했다. 하단 ScrollView를 DepthModuleDock으로 교체해 카드 위 드래그/휠/좌우 버튼을 연결하고 기본 스크롤바를 숨겼다. 하단 선택은 선택한 카드 한 개의 화면상 이동을 작업판 위에 표시한다.

관성 이동은 사용자가 원하지 않으므로 제거했다. PointerMove의 pressedButtons와 프레임의 실제 왼쪽 버튼 상태를 확인하고, 해제/취소/자신의 캡처 상실/창 이탈 시 드래그 상태를 종료한다. 자식 카드에서 탐색대로 캡처가 넘어가는 이벤트를 탐색대 자체의 캡처 상실로 오인하지 않도록 target을 검사한다.

합성 UI 이벤트를 이용한 드래그 검증은 실패했다. 이 검증 코드는 제거했으며 드래그 성공으로 기록하지 않는다. macOS 접근성 확인 결과 false여서 OS 마우스 입력 자동 검증을 수행하지 못했다. 수정본 Unity macOS 빌드 통과. 이 입력 수정은 아직 Windows EXE에 재빌드하지 않았다. 3D 시각적 품질은 여전히 사용자가 거부한 상태이며 승인/완료가 아니다.

### 2026-10-30 최신 수정 — 초기 2번 + 3번, MR 설계 5장

사용자는 6번 구현도 각도·몸체·연결 구조가 다르다고 거부하고 초기 갤러리 2번과 3번의 혼합을 요청했다. 이 요청이 이전 선택 화면의 하단 하이어라키 배치보다 우선한다.

- `Workbench23.uss`를 독립된 현재 스타일로 연결했다. 왼쪽 실제 파일/선언 하이어라키, 큰 소스 연결 프리뷰, 오른쪽 기능 구성, 하단 CLI/API 문맥과 모듈 라이브러리로 배치한다. 기존 6번 스타일 파일과 이전 시안은 보존했다.
- 실제 closure에서 역할별 대표 모듈을 최대 6개 표시한다. 표시는 선언 종류·이름·소스 참조 수에 따른 선택이며 의미적 모듈 추론 완료를 뜻하지 않는다. 전체 관련 요소는 별도 목록으로 접근한다. 프리뷰 에셋도 실제 인덱스 ID와 이미지를 사용한다.
- 카드에는 방향이 있는 실제 호출·참조선, 숫자 속성 입력, 소스 발췌, 원본 코드 진입을 연결했다. 공유 계산 함수의 할인 값 참조는 다른 카드 위를 통과하지 않도록 바깥 경로를 사용한다. 프리뷰 버튼과 선택 기능의 매핑도 표시한다. 관계는 실행 순서 검증이 아니다.
- 6번의 하단 가로 슬라이더를 현재 작업뷰에서 제거하고 파일 그룹/개별 모듈 라이브러리로 바꿨다. 스크롤은 기본 휠/트랙패드를 유지하고 독립된 작은 세로 레일을 쓴다. 레일 드래그는 누른 동안만 값을 바꾼다.
- 실제 macOS 앱에서 1680×1000, 1280×720, 1024×768의 카드 경계·쌍별 겹침·버튼과 소스 footer 겹침·주요 패널 경계 및 순서를 검사했다. 캡처를 직접 확인했다. 이 검사는 실제 OS 마우스 클릭/핸드 트래킹 자동화가 아니다.
- `/private/tmp/native-smoke-ref23` 격리 복사본에서 20→25 제안·검토·적용·재분석, 합계 96→90, 안정적인 모듈 ID를 확인했다. [결과 JSON](screenshots/2026-10-30-reference23/native.json). 저장소 `samples/Checkout`은 변경하지 않았다. 대상 프로젝트 빌드와 런타임 동작 검증은 수행하지 않았다.
- 최종 macOS 앱과 Windows EXE 빌드 성공. Windows 실행은 검증하지 않았다. 빌드 로그는 로컬 `/tmp/depth-ref23-package-mac.log`, `/tmp/depth-ref23-package-windows.log`에 남아 있다.
- 현재 PC 표면은 UI Toolkit의 절차적 메시·층·음영이다. MR 레퍼런스의 실제 공간 광학 표현, headset 렌더링, 양안/손 입력을 구현한 것은 아니다. 사용자 시각적 최종 승인도 없다.

### MR 레퍼런스 긍정 피드백 이후 — 실제 PC 공간뷰

사용자가 MR 레퍼런스를 좋아한다고 밝히고 PC도 같은 방향으로 구현하라고 요청했다. 기본 진입을 `Spatial workspace`로 바꾸고 기존 2+3 정면 편집뷰는 `Workbench`에 보존했다.

- `DepthSpatialField`는 원근 카메라·실제 입체 몸체·유리 가장자리·소스에서 렌더링한 표면·바닥 그림자·작은 부유 움직임을 사용한다. 중앙의 읽기 가능한 프리뷰 주변에 실제 모듈을 최대 10개 표시한다. 역할별 선택은 이름·선언 종류·참조 수에 따른 표시 규칙이며 범용 의미적 모듈 추론은 아니다. 나머지는 검색·Project·More modules로 탐색한다.
- 모듈을 선택하면 같은 몸체가 전진하고 정면으로 회전한다. 원래 위치에는 윤곽을 남기며, 다른 모듈은 자기 위치를 유지한다. 공간을 종료하지 않고 소스·관계·목적/설계 근거·속성 초안·검토 흐름에 접근한다. 실제 소스에서 확인한 호출과 참조만 연결한다.
- 드래그 시작/이동/해제/취소/캡처 상실을 처리하며 버튼을 누르지 않은 움직임은 카메라를 바꾸지 않는다. Overview는 선택 몸체를 되돌리고 시점을 초기화한다. Motion은 자동 부유를 끈다.
- 실제 macOS 앱의 Physics ray 선택, 선택한 몸체만 이동, 동일 ID 복귀, 실제 코드 조회, 속성 초안 20→25와 프리뷰 96→90, 초안 이후 원본 값 유지, 드래그 해제 후 정지를 검증했다. 초안에는 `Draft · not applied`를 표시한다. 이번 공간뷰 테스트는 저장소 소스에 변경을 적용하지 않았다.
