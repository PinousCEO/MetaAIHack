다음 CLI는 이 문서 → [AGENTS.md](../AGENTS.md) → [전날 실패 기록](HANDOFF-2026-10-29.md) 순서로 읽는다. 이전 기록을 삭제하거나 이전 거부된 디자인을 승인된 것으로 바꾸지 않는다.

## 사용자 요청과 현재 판단

- Depth AI는 실제 코드·에셋을 모듈로 이해하고 수정·재사용·재구성하는 플랫폼이다. Checkout은 소스 연결을 검증하는 예제다.
- 사용자는 6번 구현을 거부한 뒤 초기 2번+3번 혼합으로 방향을 바꿨고, 이후 MR 레퍼런스 5장에 긍정적으로 반응하며 PC도 중앙 프리뷰 주변에 모듈이 떠 있는 형태로 요청했다.
- **MR 참고 이미지 방향에 대한 긍정 피드백만 있다. 현재 PC 구현의 최종 시각적 승인은 없다.** 빌드·기능 테스트를 디자인 승인으로 바꾸지 않는다.
- 유사 제품 조사 후 사용자는 “개선 방법을 제시하고 그대로 구현”하라고 요청했다. 오늘 마지막 구현 범위는 공유 구현의 영향 분석, 변경 검토 검사, 사람·에이전트 공통 문맥이다.
- 마지막 추가 요청: 오늘 작업을 Git에 푸시하고 다음 CLI가 읽을 오늘 작업/남은 작업을 정리. 이 문서와 AGENTS 진입점을 함께 커밋한다.

## 오늘 구현한 것

### PC 편집뷰, 공간뷰, MR 설계

- 초기 2번의 하이어라키/프리뷰/오른쪽 구성과 3번의 밝은 몸체를 섞은 `Workbench`를 보존했다. 기존 거부된 6번 스타일도 파일로 남아 있다.
- 기본 `Spatial workspace`: 중앙의 정면 프리뷰 주변에 실제 소스 ID 모듈 최대 10개를 표시. 선택한 몸체만 전진·정면 회전, 원래 위치 윤곽, 참조선, 선택 작업판, Overview 복귀를 연결했다.
- 검색·Project·More modules로 나머지 소스에 접근한다. 카메라는 누른 채 드래그할 때만 움직인다. Motion의 자동 부유와 포인터 카메라 입력은 별개다.
- MR 참고 이미지 5장과 프롬프트를 `design/references/mr-workspace-20261030/`에 보존했다. **XR 기기 뷰어는 구현하지 않았다.**

### 공유 구현의 변경 영향 분석

- 선택 모듈의 `Impact` 탭에서 직접/간접 사용처와 사용자 → 변경 대상 방향의 소스 경로를 보여준다. 파일·행·관계 근거를 유지한다.
- `CalculateTotal`의 직접 사용자 `ApplyCoupon`, `Estimate`가 하나의 계산 함수 ID를 참조한다. `DiscountPercent`는 계산 함수를 통해 두 사용자에게 이어진다.
- `Show affected in space`는 해당 ID만 공간에서 보여주는 필터다. 코드 복제·통합·기능 재구성이 아니다. `Show all modules` 또는 `Overview`로 전체 복귀.
- 정적 `calls/references/constructs/inherits/view-asset`의 역방향 탐색. `contains` 제외, ID 중복 제거, 사용자별 최단 근거 경로 하나. 최대 6단계/128개와 생략 여부 표시.
- 이는 **잠재 영향**이며 실행 동작 변화의 증명이 아니다. 미해석/동적 참조, 프로젝트 구성 의존 관계는 빠질 수 있다.

### 변경 검토와 적용 검사

- 기존 C# 선언의 구문 토큰을 비교해 실제 수정 ID를 잡는다. 자식 메서드 수정으로 상위 타입 전체를 수정했다고 표시하지 않는다. 주석/공백은 무시.
- 추가 선언·지원하지 않는 문법/언어·모호한 매핑은 보수적인 파일 범위로 넓히고 그 사실을 표시한다. 범용 의미적 diff는 아니다.
- 검토 화면의 `Impact & checks`: 수정 ID, 영향 범위, 스냅샷·파일 해시·C# 구문 검사. C# 수정이 없으면 구문 검사도 `not-run`이다.
- 대상 프로젝트 빌드와 행동 테스트는 항상 `not-run`으로 구분한다. Roslyn 구문 파싱은 컴파일/동작 검증이 아니다.
- Apply에서도 독립적으로 검사를 강제한다. 잘못된 C# 구문은 UI를 우회해도 소스에 적용하지 못한다. 변경 이력에 `assessment.json` 저장.

### 사람과 AI가 공유하는 문맥

- `Impact → AI context`에서 실제 에이전트에 전달되는 것과 같은 문맥 패킷을 읽고 복사한다.
- 선택 ID·소스 revision·해시·소스 발췌·설계 기록의 출처/만료 상태·영향 경로·생략 수가 포함된다. 최대 24개 후보 포함/24,000자. 긴 발췌와 누락은 명시한다.
- UI, HTTP, MCP, CLI 초기 프롬프트, API 에이전트 초기 문맥이 같은 생성기를 사용한다. 에이전트는 여전히 추가 소스를 조회할 수 있다. 전체 실행 문맥/토큰 사용량이 항상 같다는 뜻은 아니다.
- 선택 revision이 낡으면 거부하며 파일 변경 후 새 packet ID가 생긴다. 전체 파일 교체 제안에는 별도 `source.read(wholeFile=true)`가 필요하다.
- 새 MCP 도구 `modules.impact`, `modules.context`, `changes.review`. 전체 도구 8개. HTTP `POST /impact`, `POST /context/packet`, 기존 `GET /proposals/{id}`의 `assessment` 확장.
- 문맥 예산은 문자 수이지 모델 토큰 수가 아니다. 토큰/비용 절감이나 정확도 개선은 측정하지 않았다.

## 검증과 패키지

- 서비스 self-test **54 assertion 통과**. 공유 호출, 간접 경로, 중복/순환, 깊이/노드 제한, 선언별 변경, 잘못된 구문 적용 거부, 실제 긴 소스의 문맥 제한과 생략, 만료 revision, API fake provider 문맥 ID를 검사했다.
- `tests/native_workspace.py`: 실제 HTTP + stdio MCP import/draft/review/apply/reindex와 문맥 패킷 동일성 통과. 실제 모델/API 계정 호출은 없다.
- Unity macOS 실제 표시 앱 `--depth-impact-smoke`: 두 공유 사용자, 경로, 공간 필터 ID, 문맥, 검토 검사, 격리 복사본 20→25 적용, 프리뷰 식 모델 합계 96→90, ID 유지/문맥 revision 변경 통과. 저장소 샘플은 변경하지 않았다.
- 1680×1000/1280×720/1024×768의 패널 경계와 프리뷰/영향 패널 겹침 검사, 실제 캡처 직접 확인. [검증 파일](screenshots/2026-10-30-impact/validation.txt).
- 같은 날 PC 공간뷰 smoke는 ray 선택/선택 몸체만 이동/복귀/드래그 해제 정지/소스와 초안도 검사했고, 기존 Workbench 별도 레이아웃 smoke도 통과했다. 이전 근거는 `2026-10-30-pc-spatial`, `2026-10-30-reference23`에 보존했다.
- 네이티브 smoke는 앱 내부 콜백·ray·상태·렌더링 검사다. 실제 OS 포인터 주입, Windows 최종 런타임, 헤드셋 손/시선 입력은 미검증.
- 최종 Unity macOS/Windows 빌드 성공. 로컬 파일은 `artifacts/macos/Depth AI.app`, `artifacts/windows/Depth AI.exe`. 빌드 출력과 런타임은 Git 제외.
- macOS에서 생성된 서비스 apphost가 AMFI/시스템 정책에 종료됐다. macOS 앱은 공식 ASP.NET Core 8.0.33 arm64 배포본의 `runtime/dotnet`으로 서비스 DLL을 실행하도록 변경했다. 다운로드 SHA-512를 공식 release metadata와 대조한다. 이 방식으로 앱/서비스 실행을 검증했다. 시스템 보호 설정은 바꾸지 않았다.
- **서명/공증 배포 완료 아님**: 공식 배포본 체크섬 일치와 실제 실행은 확인했지만 `codesign --verify`는 호스트에 invalid signature를 보고했다. 서명 검사 통과라고 주장하지 않는다. macOS/Windows RID publish에는 Roslyn CS8012 경고 2건이 남는다.

## 다음 CLI의 재현 명령

Unity 6000.3.13f1, .NET **SDK 8**, Python 3.12+ 필요. SDK 9/10 Roslyn을 net8에 직접 참조하지 않는다.

```sh
artifacts/dotnet/dotnet run --project src/Depth.Service -c Release -- --self-test
PATH="$PWD/artifacts/dotnet:$PATH" python3 tests/native_workspace.py
bash scripts/build-macos.sh
```

`tests/native_workspace.py`가 새 `artifacts/native-workbench-fixture.json`과 `.allow-smoke-apply` 있는 격리 복사본을 만든다. 그 경로로 앱 실행:

```sh
open -n 'artifacts/macos/Depth AI.app' --args --depth-impact-smoke --depth-project '<fixture.project>' -logFile /tmp/depth-impact-player.log
```

검사는 `native-smoke-` 이름+marker를 모두 요구한다. 이미 25로 적용한 복사본으로 재실행하지 말고 새 fixture를 만든다. 일반 사용 앱과 테스트 앱을 동시에 열면 기본 port43821 충돌이 난다. 자신이 실행한 테스트 앱만 종료한다. 샘플/사용자 프로젝트를 테스트용으로 덮어쓰지 않는다.

- macOS 배포 시 `.app` 옆 `service`, `runtime`, `sample` 모두 필요하다. 자동 `package-macos-runtime.py`는 네트워크에서 메타데이터를 읽는다.
- Windows 빌드: 기존 `scripts/build.ps1`과 `DepthBuild.Windows`. macOS 호스트에서 Unity Windows 타깃 크로스 빌드는 가능하지만 실행 검증과 다르다.
- 로컬 최종 로그: `/tmp/depth-impact-mac-final.log`, `/tmp/depth-impact-windows-final.log`, `/tmp/depth-impact-final-player.log`, `/tmp/depth-impact-final-self-test.log`.

## 남은 작업 — 우선순위와 완료 기준

1. **현재 실제 PC 화면의 사용자 피드백 반영.** MR 기준과 실제 캡처를 나란히 보고 재질·가독성·밀도·아이콘·선택 이동을 맞춘다. 검증 통과로 디자인 승인 대체 금지. 작은 해상도의 가독성, 긴 이름/많은 영향 경로, 실제 마우스/휠 동작도 확인.
2. **대상 프로젝트 검증 실행기.** 사용자가 정한 빌드/테스트 명령과 환경을 저장하고 격리된 변경에서 실행, 결과·실행 로그·revision 연결. 그 전까지 `not-run` 유지. 지금 앱 자체 빌드 성공과 가져온 대상 프로젝트 빌드를 혼동하지 않는다.
3. **실제 프로젝트에서 문맥 효과 측정.** 같은 변경 작업으로 일반 전체 문맥과 Depth 문맥을 비교해 성공률·누락 참조·토큰·지연을 기록. 현재는 긴 합성 소스와 작은 Checkout 검증만 있다. 실제 API/CLI 계정 end-to-end는 아직 없다.
4. **분석 범위 확대.** 실제 csproj/Unity asmdef와 조건부 컴파일/패키지 로딩, Dart 의미적 관계, Web/React·Flutter 실제 UI 요소 ↔ 소스 매핑. 현재 Checkout preview adapter는 범용 앱/웹/게임 프리뷰가 아니다.
5. **변경 검토 품질.** 정확한 줄 diff/변경 부분 강조와 추가·이동·삭제·오버로드·partial·지원 외 문법의 매핑 정교화. 보수적 파일 fallback을 숨기지 않는다. 원본 행동 보존과 리팩터링 안전성은 미구현.
6. **MR 실제 뷰어.** 동일 ID/선택/revision 문맥을 쓰는 XR renderer, 읽기 가능한 정면 조작판, 시선·손/컨트롤러 선택, 공간 배치 저장. 헤드셋과 런타임을 정한 뒤 실제 기기 검증. 생성 이미지 5장과 구현 완료를 구분.
7. **배포/규모.** macOS 서명·공증과 깨끗한 시스템 실행, Windows 실제 실행, 수천 모듈 성능, 다중 앱 인스턴스, 취소/시간초과, 영속 제안·복구, 공통 ID 기반 실제 재사용/재구성 도구.

유사 프로젝트에서 얻은 방향: [Haystack 공개 Editor 저장소](https://github.com/haystackeditor/haystack-editor)의 공간 코드 탐색, [CodeCharta](https://codecharta.com/docs/overview/introduction/)의 구조·지표 시각화, [Cursor Design Mode](https://cursor.com/docs/agent/design-mode)의 요소 선택 기반 수정, [ShapesXR](https://learn.shapesxr.com/)의 공간 프로토타이핑과 일부 기능이 겹친다. Depth의 차별화 **목표**는 실제 소스/공유 ID/근거/검증/PC·MR 공통 문맥의 연결이다. 유일한 제품, 업계 영향 확정, 검증된 토큰 절감으로 표현하지 않는다.
