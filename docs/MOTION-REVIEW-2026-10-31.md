# 화면 전환과 애니메이션 수정 — 2026-10-31

사용자가 기능 검사만으로는 애니메이션과 UI/UX의 어색함을 확인할 수 없다고 지적했다. 이번 작업은 실제 Play Mode의 전환 중간 프레임을 캡처하고 확인하면서 진행했다. 레퍼런스와 기존 화면도 비교했다. 사용자 시각적 최종 승인이나 제품 전체 완성을 뜻하지 않는다.

## 변경한 흐름

| 흐름 | 변경 |
|---|---|
| 모듈 선택 | 소스 응답 뒤 별도로 0.9초를 기다리는 구조 제거. 클릭 시 이동 시작, 로딩 상태 표시, 몸체 도착 진행도에 맞춰 정면 작업판 표시. 늦게 도착한 이전 선택 응답은 계속 폐기한다. |
| 복귀·빠른 재선택 | 현재 위치/회전/크기부터 이어서 이동한다. 복귀 중 패널을 즉시 삭제하지 않고 입력을 막은 뒤 사라지게 한다. |
| 몸체와 글자 | 카드 글자가 큰 편집판 크기로 늘어나는 프레임을 발견해 수정했다. 확대 전 카드 글자를 숨기고 복귀해서 작아진 뒤 다시 보여준다. |
| 갱신·테마·리사이즈 | 같은 프로젝트/ID의 이동 상태를 갱신 전후에 보존한다. 창 크기 변경도 새 배치 목표를 따라가며 위치 초기화를 피한다. |
| 연결선 | 선택/복귀/다른 모듈 선택에 따라 180ms 동안 나타나거나 사라진다. 이동 중에도 실제 참조의 양 끝을 따라간다. |
| 모달 | 열기 180ms, 닫기 140ms. 교체되는 창은 이전 닫기 완료에 제거되지 않는다. 닫힌 창은 즉시 응답 적용 대상에서 제외하며 이미지·설명 콜백도 이를 확인한다. |
| 프로젝트·AI 패널 | 열기/닫기 이동과 불투명도 전환. 서로 겹쳐 열리지 않도록 버튼 동작을 연결했다. 글자 뒤에 모듈이 비치는 정도를 줄였다. |
| 콘텐츠·결과 | 탭, 소스 응답, 수준별 설명, 생성 이미지, 확정 프리뷰 갱신에 짧은 표시 전환. 숫자를 편집하는 draft는 매 입력마다 깜빡이지 않게 유지한다. |
| 채팅 | 새 항목 표시와 부드러운 자동 스크롤. 과거 메시지를 읽고 있으면 위치를 강제로 아래로 옮기지 않는다. 휠 입력은 진행 중 자동 스크롤을 취소한다. |
| 버튼·로딩 | hover/pressed/focus 색상 피드백. 짧은 요청에는 표시하지 않고, 진행 중 요청에만 상단 활동 표시를 보여준다. 완료율을 추정해 표시하지 않는다. |
| 모션 줄이기 | 공간 이동/부유와 UI 전환을 즉시 완료하고 활동 표시도 고정한다. 마지막으로 숨겨진 패널 재표시 시 opacity를 복원하도록 보완했다. |

`DepthMotion.cs`는 요소별 전환을 하나만 소유하고 중단·재시작을 처리한다. `DepthSpatialField.cs`는 공간 몸체와 연결선을 담당하며, `Motion.uss`는 상호작용 피드백을 담당한다. 프레임별 씬 검색을 추가하지 않았다. 서비스/Meta 모델 계약은 변경하지 않았다.

## 실제 확인한 결과

- 첫 전환 검사: `artifacts/unity-live-20261031-200803/report.json`, 3회 반복을 포함한 28개 통과.
- 후속 검사: `artifacts/unity-live-20261031-201133/report.json`, 32개 통과. 이전 실제 Meta 생성 PNG를 UI에 재생해 표시/닫힘 전환을 검사했다. 새 모델 생성 호출로 주장하지 않는다.
- 글자 확대 문제 수정 후: `artifacts/unity-live-20261031-201438/report.json` 및 `artifacts/unity-live-20261031-201529/report.json`, 각각 32개 통과. 마지막 기록의 연속 프레임 62장/12개 전환을 검토용 영상으로 묶었다.
- 영상: `artifacts/unity-live-20261031-201529/motion-review.mp4`.
- 프레임 선택·재생 페이지: `artifacts/unity-live-20261031-201529/motion-review.html`.
- 원본 위치/불투명도/시간: 각 실행 폴더의 `motion-frames.json`. 캡처는 약 10fps 표본이며 30fps로 인코딩한 영상은 실제 성능 측정이나 OS 포인터 자동화 영상이 아니다. UI 처리기와 상태 전환을 호출한 실행이다.
- 선택·복귀·모달·이미지 화면의 중간 프레임을 직접 열어 확인했다. Unity의 실제 compiler response를 사용하는 런타임 및 Editor 참조 컴파일도 통과했다.

## 정확히 남은 검증

최종 소스의 `RevealUi`에 모션 줄이기가 켜져 있을 때 opacity/translate를 즉시 복원하는 보완을 넣고, 숨겨진 보조 패널 재열기 2개 검사를 추가했다. 이 보완은 참조 컴파일까지 통과했다. 마지막 실제 Editor는 런타임 DLL 20:14:26, 테스트 DLL 20:10:50을 사용하므로 **새 34개 전체 검사 통과라고 쓰지 않는다.** 현재 실제 결과는 32개다. MetaAIHack에서 Refresh 후 같은 모션 검사를 실행해야 한다.

처음 MCP는 MetaAIHack에 연결됐고 대상 확인 후 Refresh도 한 차례 성공했으나, 이후 호출은 WorldVR로 바뀌었다. 모든 변경 명령은 경로 가드로 막았으며 WorldVR는 수정하지 않았다. 실제 검사는 MetaAIHack의 명시적 프로젝트 로컬 검증기로 실행했다. 새 Windows EXE 빌드, 모든 해상도/입력 기기의 UX, 사용자 디자인 승인은 미확인이다. 이전 실제 이미지 생성 UI 전체 인수 검사와 리소스 재진입 검증도 이번 제한된 이미지 표시 재생으로 대체하지 않는다.

## 재개

MetaAIHack Editor에서 소스 Refresh 완료를 확인한 뒤 `artifacts/unity-motion-only.txt`에 `motion`, `artifacts/unity-verification-command-v2.txt`에 `start`를 기록하면 API 재호출 없이 모션 검사를 수행한다. 결과가 34개인지와 최신 소스가 Editor에 반영됐는지를 함께 확인한다. 다른 프로젝트의 모델/씬을 변경하지 않는다.
