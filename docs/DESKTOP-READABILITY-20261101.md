# 영어 UI · 모듈 역할·연결·설계 근거 개선

사용자는 이전 실제 화면이 여전히 읽기 어렵고 아이콘 잘림, 반복되는 연결점, 다크/라이트 모드 누락, 영어 기반 UI 누락, 설계 근거 부족을 지적했다. 이전 화면을 시각적 승인으로 취급하지 않는다. 이번 변경은 실제 Electron 코드이며 새 생성 이미지나 Unity/MR 구현이 아니다.

## 구현한 동작

- 기본 HTML 언어와 메뉴·조작·검토·에셋·상태 문구를 영어로 변경했다. 신규 Meta 분석/변경 이유의 기본 지시도 영어다. 소스 식별자·기존 코드 주석·저장된 설명 원문은 임의로 번역하거나 바꾸지 않는다. 이전 한국어 캐시는 원문을 유지한다.
- 오른쪽 위 테마 버튼으로 light/dark를 전환하고 `depth.theme`에 저장한다. 외곽, 작업면, 검사창, 모듈, 변경 검토, 소스 패널, 대화상자에 각각 테마 색을 적용한다. 에셋 이미지에 색상 반전 필터를 쓰지 않는다. 프로젝트 자체 프리뷰는 원래 디자인을 유지한다.
- 잘못된 기어 도형을 교체하고 SVG의 viewBox를 패딩 있는 `-2 -2 28 28`로 통일했다. 축소 모드에서도 아이콘을 유지한다. 몸체 크기와 배치 계산을 240×180으로 일치시켰으며 자동 배치는 실제 표시 영역에 맞춰 열 수를 고른다. 사용자가 드래그한 배치는 전체 보기로 지우지 않는다.
- `visual-model.js`가 실제 관계로 모듈을 operation/coordinator/state/container/interface/asset으로 구분한다. 서로 다른 모서리·탭·테두리·색·아이콘·역할 문구를 사용한다. Coordinator는 서로 다른 직접 호출 대상이 2개 이상인 함수다. Shared는 포함/역방향 view-owner를 제외한 직접 소비자가 2개 이상인 경우다. 이름만 보고 알고리즘이나 비즈니스 중요도를 추정하지 않는다.
- 상단 Key connections는 함수의 `서로 다른 직접 소비자 수 × 2 + 직접 호출 대상 수`로 최대 3개를 표시한다. 버튼으로 실제 ID를 선택한다. 수치의 기준을 툴팁에 공개하며 전체 모듈을 제거하거나 대표 몇 개로 대체하지 않는다.
- 구성판은 관계마다 붙이던 원을 없애고 몸체당 입력/출력 연결점으로 모았다. 모든 관계 ID를 보존하고 기본 Selected links에서는 선택 모듈의 연결만 강조한다. All links로 전체 선을 볼 수 있다. 무관한 몸체는 흐려지며 화면에서 삭제하지 않는다. 지도는 같은 출발/도착/종류의 중복 선과 역방향 view-owner 선을 줄이고 선택한 관계를 표시한다. 원본 소스 관계 목록은 별도로 유지한다.
- 선택된 연결의 움직이는 점선은 의존 방향을 나타낸다. 런타임 실행 순서나 실행 기록이 아니며 화면에 static source라고 표시한다. 모션 줄이기와 OS reduced-motion 설정을 따른다.
- 검사창의 구조 설명은 실제 관계 종류·사용처·의존성·소스 위치를 보여 준다. Read full design rationale은 넓은 대화상자에 목적·설계 개념·작동 방식·이유·예시·대안·주의점과 정확한 소스 인용을 표시한다. 인용 버튼은 실제 원본 위치를 연다. 모듈 내부 화면에도 같은 설명을 표시하며 수준 변경은 같은 저장된 사실을 다시 표현한다. 기능 묶음 설명임을 명시하고 선택과 다른 그룹의 설명은 표시하지 않는다. Meta 설명이 없을 때는 구조적 사실과 미생성 상태를 구분한다.

## 검증과 남은 확인

- 최신 렌더러 DOM + 실제 서비스 검사 **104개** 통과: `artifacts/desktop-dom-1793511296400/report.json`, `artifacts/readable-dom-final.log`. 테마 저장/선택 유지, 영어 메뉴, 포트 수, 역할 구분, 전체 관계 유지, 구조 설명, 기존 드래그·선택·소스·적용/undo 흐름을 포함한다. 실제 픽셀 검사가 아니다.
- 제품 흐름 **39개** 통과: `artifacts/cohesion-contract-1793511107041/report.json`, `artifacts/readable-product.log`. 전체 설명과 정확한 인용·코드 링크, 중앙 설계 설명을 추가 확인했다. 모델 응답은 fixture이며 실제 파일·복사본 빌드/실행이다. 마지막 설명 ID 가드 후 재검사는 `artifacts/readable-product-final.log`에 별도 기록한다.
- 영어 프롬프트·문서 표제 변경 후 Meta 대상 회귀 **92개** 통과: `artifacts/readable-meta-tests.log`. 새 실제 Meta 응답 검증이 아니다. 이전 네이티브 실행은 연결 성공 후 설명의 출력 한도 실패였으며 이 사실을 변경하지 않는다.
- 새 서비스는 `artifacts/service-readable-ui/`, 실행은 `artifacts/desktop/Depth AI.exe`. UI와 신규 `visual-model.js`/`readability.css`를 함께 패키징했다. 기존 키는 번들에 넣지 않는다.
- 네이티브 `--smoke`에 다크 구성/지도/에셋, 라이트 전체 연결/자세한 설명을 추가해 기본 화면을 18장 캡처한다. 실제 조작 영역 안의 아이콘 경계, 테마 전환 전후 실제 계산 색, 프레임 표식, 이미지 디코딩과 프리뷰 경계를 검사한다. 실제 결과 파일과 픽셀을 읽기 전에는 화면이 모두 정상이라고 기록하지 않는다.

마지막 설명 ID 가드 후 제품 검사도 **39개 통과**했다(`artifacts/cohesion-contract-1793511434619/report.json`, `artifacts/readable-product-final.log`). 앱 파일 14개와 DLL의 배포본 일치 및 `.env` 제외를 `artifacts/readability-package-check.json`에 기록했다.

현재 도구의 Mojo IPC 0x5 제한이 남아 사용자에게 cmd에서 `"C:\Users\dlfgu\Documents\GitHub\MetaAIHack\artifacts\desktop\Depth AI.exe" --smoke` 시작을 요청했다. 새 `artifacts/desktop/resources/artifacts/desktop-smoke-<시각>/`를 확인해 이어간다. 현재 시점 새 18장 캡처/사용자 시각적 승인/전체 기능 완료는 미검증이다.

## 사용자 실행 후 검사 코드 오류 수정

사용자가 “시작했어”라고 답한 실행은 `artifacts/desktop/resources/artifacts/desktop-smoke-2026-11-01T05-38-44-873Z/`이다. 보고서는 **failed**, 4개 선행 검사, PNG 0장이다. 새 아이콘 검사에 잘못 붙인 `every(...)()`가 boolean 값을 함수처럼 호출했다. 오류 캡처도 같은 검사를 반복하면서 저장되지 않았다. 이 실행은 앱 기능 실패나 화면 통과의 근거가 아니다.

실제 Electron에 주입하는 문자열을 명시적 함수 호출로 수정했다. `node desktop/smoke-test.cjs`로 동일한 문자열을 실행해 정상 영역, 빈 목록, 왼쪽/아래쪽 이탈, 너비/높이 0의 6개 회귀 사례를 확인했다. 기본 npm test에도 포함했다. 실패 화면을 저장할 때는 아이콘/이미지 선행 검사를 반복하지 않으며 새로 그려진 프레임의 색상 표식 검사는 유지한다. 문법 검사도 통과했다.

수정한 검증기를 실행 폴더에 복사하고 원본/배포본 SHA-256 일치를 확인했다. 이전 패키징 기록은 보존하고 이번 검증기 수정 해시는 `artifacts/readability-smoke-fix-check.json`에 별도 기록한다. 사용자에게 같은 cmd 명령의 재시작을 요청했다. 새로운 18장 캡처와 픽셀 검토는 아직 남아 있다.
