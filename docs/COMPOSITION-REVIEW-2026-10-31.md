## 소스 변경

- 프리뷰가 왼쪽으로 이동하는 동안 탐색 공간은 페이드아웃한다. 선택된 몸체 한 장을 확대하지 않는다.
- `DepthComposition.cs`에서 구성의 모든 ID를 네이티브 UI Toolkit 카드로 표시하고 모든 카드가 같은 시간축으로 도착한다. 가까운 글자를 낮은 해상도의 RenderTexture 확대에 맡기지 않는다. 작은 창에서는 가독성을 유지하고 스크롤로 나머지 멤버에 접근한다.
- 실제 관계의 양 끝을 카드에 연결한다. 호출/참조/소유 관계 색상을 구분하고, 모듈 선택 시 그 모듈의 입출 연결을 강조한다. 정적 관계를 실행 순서로 표시하지 않는다.
- 구성 내부 카드 선택은 `composition.rootId`와 전체 카드 집합을 유지한다. 코드 탭을 왕복해도 동일 기능으로 돌아온다. 숫자 속성 draft·변경 검토와 이미지 상세 확인을 보존했다.
- 공간 클릭, 프리뷰 버튼, 하이어라키, 라이브러리와 모듈 목록의 진입을 전체 구성에 연결했다. 기존 대표 카드 6개 제한과 구성 목록 250개 제한을 제거했다.
- `WorkspaceIndex.Compose`의 5단계/256개 제한을 제거했다. 방문 집합으로 순환을 끊으면서 모든 도달 가능한 인덱싱된 의존성을 포함한다. 클래스를 직접 열면 해당 클래스의 선언 멤버도 포함한다. 다른 클래스에 대한 단순 참조만으로 무관한 형제 메서드를 끌어오지는 않는다.
- 해결되지 않은 동적 호출·리플렉션·외부 런타임 의존성까지 모두 발견한다는 뜻은 아니다. 원본 파일의 자동 분할/통합이나 Meta 품질을 새로 검증한 작업도 아니다.

## 검사와 한계

- 최신 서비스 별도 Release 빌드 성공: `artifacts/service-composition/`.
- 전체 205개 검사 통과: `artifacts/self-test-composition.log`. 300개 깊이의 순환 호출 전체, 마지막 순환 연결, 무관한 함수 제외, 클래스 소유 멤버 301개를 별도로 검사했다. 첫 204개 성공 후 클래스 사례를 추가한 재실행은 OOM으로 끊겼고 기록은 `self-test-composition-interrupted.log`에 있다. `DOTNET_gcServer=0`으로 다시 실행해 205개를 통과했다. 기존 Meta 검사는 fixture다.
- 런타임 C#은 실제 Unity compiler response로 성공했다. Editor 검사 코드는 기존 Editor response의 복사본에 새 파일을 포함하고 최신 런타임 참조를 지정해 컴파일했다. 별도 컴파일 출력은 실제 Editor DLL이 아니다.
- `DepthCompositionChecks.cs`에 실제 프리뷰 버튼 submit, 3회 선택/복귀, 전체 멤버·연결, 하위 카드 클릭 후 구성 유지, 코드 왕복, 빠른 재선택, 클래스 구성, 속성 draft, 다크, 1280/1600 레이아웃, 마지막 모듈 스크롤 접근, 모션 줄이기를 검사하도록 추가했다. **아직 실행하지 못했다.** OS 포인터 자동화나 실제 창 크기 변경 검사라고 주장하지 않는다.

## 현재 실행 차단

처음 MCP는 MetaAIHack를 확인했으나 이후 WorldVR로 바뀌어 변경을 경로 가드로 막았다. 후속 호출은 미응답이었다. 대상 경로를 고정한 relay도 연결 거부/시간 초과였다. MetaAIHack의 명시적 검증 명령으로 진입을 요청했으나 Editor.log가 `Reloading assemblies for play mode.`에서 멈췄다. 실제 DLL은 20:37:11 버전이고 새 결과 폴더나 캡처가 없다. 사용자에게 Unity 창 상태를 비동기로 물었으며 답변을 받지 못했다.

20:52에는 디스크 가용 공간 0과 컴파일 출력 쓰기 오류도 발생했다. 이번 임시 디버그 파일/재생성 가능한 검증 리소스 일부를 정리해 참조 컴파일을 복구했다. 이전 `artifacts/service-agent-check` 폴더 정리는 자동 승인 검토에서 정책상 거부되어 실행하지 않았다. 세부 거부 이유는 제공되지 않았다. 기존 디자인 이미지·캡처·프로젝트 소스를 삭제하지 않았다.

정상 Release 경로는 과거 검증 서비스 PID 39740(18:12:05 시작)이 잠그고 있다. 경로와 시작 시각을 확인한 종료 시도도 접근 거부였다. exe/DLL 갱신을 성공했다고 쓰지 않는다. 잠금 파일을 우회해서 덮어쓰거나 다른 Unity 프로젝트를 종료하지 않았다.

## 복구 후 필요한 작업

1. MetaAIHack의 멈춘 진행창/팝업과 디스크 공간을 확인한다. 프로젝트 로컬 명령의 대기 중 `stop`을 먼저 처리하고 테스트 오브젝트·환경 복원을 확인한다.
2. 기존 검증 서비스를 정상 종료한 뒤 일반 Release를 빌드한다. AssetDatabase.Refresh 후 새 `DepthCompositionChecks.cs`가 실제 Editor response에 포함됐는지, runtime/Editor DLL이 모두 최신인지 확인한다.
3. `artifacts/unity-composition-only.txt`에 `composition`, `artifacts/unity-verification-command-v2.txt`에 `start`를 기록하면 새 검사가 동작한다. 코드가 최신인지 확인하기 전 시작하지 않는다. 기존 `unity-motion-only.txt`도 새 검증기에서 소비되지만 결과는 새 구성 검사를 기준으로 확인한다.
4. 실제 전체 구성/중간 프레임/작은 창/속성 편집을 직접 캡처해 검토한다. 모듈 누락, 선의 가독성, 잘린 글자와 겹침이 있으면 수정 후 다시 실행한다. 현재 소스를 시각적으로 완성됐다고 보고하지 않는다.
