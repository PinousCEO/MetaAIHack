# 프리뷰 중심 레퍼런스의 기본 앱 반영

사용자의 “작업해”를 최근 14장 레퍼런스를 기준으로 구현을 재개하라는 지시로 받아 진행했다. Unity/MR을 되살리지 않고 기존 Electron/.NET 제품을 수정했다. 14장 전체 기능 완성이나 시각적 일치 승인은 아니다.

## 반영 내용

- `desktop/ui/workspace.js`와 `workspace.css`가 기존 기능의 공통 외곽을 구성한다. 탐색·설명·분리·통합·에셋·검토 메뉴를 상단에 두고, 기본 Composition 화면의 프리뷰가 작업면의 44%를 차지하도록 했다. Expand로 같은 화면에서 확대한다. 작은 창은 세로 배치한다.
- 실제 서비스의 구성/관계/소스 ID를 사용하는 기본 앱에 Field Guide, Route Atlas, Orbit을 연결했다. 보기와 테마를 저장하며 선택과 구성 root는 유지한다. Route Atlas는 방향 의존성의 최단 거리별 열, Orbit은 중심과 겹치지 않는 고리 배치다. 배치 거리를 수학적 중요도나 실행 순서라고 해석하지 않는다.
- 프리뷰에서 선택한 텍스트·값·이미지·버튼의 선언, 직접 의존 대상, 실제 소스를 구성 아래에 즉시 표시한다. 총액은 CalculateTotal 발췌를 먼저 보여 준다. 연결된 소스로 이동해도 원래 프리뷰의 전체 구성을 유지한다. 어댑터 없는 프로젝트와 빈 프로젝트에는 예제나 이전 소스를 남기지 않는다.
- 기존 실제 검사창을 구성 아래로 옮기고, 분리·통합·에셋·검토 화면에서는 옆으로 돌린다. 검사창을 복제하거나 기능을 장식으로 대체하지 않았다. 초보자/숙련자 설명, AI 문맥, Meta 요청, 승인·적용·undo 경로를 유지했다.
- 로직·상태·에셋의 형태와 색을 구분했다. 반복 관계는 출발/도착/종류별 한 선으로 보이지만 모든 canonical ID를 유지한다. 선을 선택하면 원본 발생 근거들을 함께 표시한다. 경로 탐색은 노드를 피하고 실제 두 포트에서 출발·도착한다. 실제 소스 값과 프리뷰 계산 결과를 구분한다.
- 기존 레퍼런스의 화살표/타입 오기를 데이터에 복사하지 않았다. 3D 스타일 PNG와 실제 메시를 구분하며 새로운 GLB 기능은 구현하지 않았다.

## 확인한 범위

- 최신 기본 앱 DOM + 실제 HTTP 서비스: `artifacts/desktop-dom-1793586016230/report.json`, **187개**. 19개 선언 바인딩 전부, 소스 즉시 표시, 보기 전환별 전체 ID, 모듈 몸체 기하 겹침, source/root 구분, 3회 소스 왕복, 실제 파일 승인/undo, 프로젝트 전환·빈 프로젝트를 확인했다. 브라우저의 글자 픽셀이나 실제 화면 검사가 아니다.
- 기존 스타일·기하 검사: `artifacts/style-study-checks-1793586016849/`, **172개**. 경로 함수에 선택적 포트 인자를 추가한 뒤 기존 기본 경로도 확인했다.
- 캡처 검수기의 기존 주입식 회귀 **6개**와 변경 JavaScript 구문 검사를 통과했다.
- 최종 제품 흐름 **39개** 통과: `artifacts/cohesion-contract-1793586207561/`, `artifacts/reference-product-final-20261102.log`. 명시적 Meta/이미지 fixture와 실제 복사본 빌드·실행·적용을 사용한다. 새 실제 Meta 호출이 아니다.
- `artifacts/reference-package-20261102.json`: 배포 UI/캡처 코드 **20개** SHA-256 일치. `.env`를 번들에 넣지 않았다. 서비스와 Electron 런타임은 이번 UI 작업에서 바꾸지 않았다.

초기 검사에서 메뉴 탐색용 `data-screen`을 body 상태에도 쓰면 버튼 대신 body를 선택하는 충돌을 발견해 `data-workspace-screen`으로 분리했다. Orbit 고리의 사선 이웃 몸체 겹침도 발견해 간격을 수정한 뒤 재검사했다. 모든 바인딩 검사로 확장하면서 테스트의 과거 5개 클릭 순서에 의존하던 Back 기대값을 실제 직전 root를 기록하도록 바꿨다.

## 실제 화면은 아직 미검수

직접 실행을 재시도했다. 수정 전 `artifacts/reference-native-20261102/stderr.log`와 배포 후 `artifacts/reference-native-final-20261102/stderr.log` 모두 **Mojo IPC Access denied (0x5)**로 종료됐다. 최신 시도의 PID는 2820이며 실제 PNG는 없다. sandbox·ACL을 바꾸지 않았다.

기본 `--smoke`에 세 보기의 큰 프리뷰 경계, 동일 구성 ID, 즉시 계산 소스, 실제 글자/아이콘 경계, 소스 스크롤 및 다크 화면 캡처를 추가했다. 이 검사 절차가 실행을 통과한 것으로 기록하지 않는다. 사용자에게 일반 cmd에서 아래 실행을 요청했다. 새 캡처를 에이전트가 직접 열어 시각 문제를 수정해야 한다.

```cmd
"C:\Users\dlfgu\Documents\GitHub\MetaAIHack\artifacts\desktop\Depth AI.exe" --smoke
```

출력: `artifacts/desktop/resources/artifacts/desktop-smoke-<새 시각>/report.json`, `index.html`, PNG. 이전 11월 1일 캡처를 이번 수정 성공 증거로 쓰지 않는다.

## 남은 범위

실제 글자·아이콘 가독성/레퍼런스 유사도/전환 모션 검수, 새 기본 앱의 실제 Meta 설명·분리·통합·이미지 호출, AI용 주석 편집 흐름의 레퍼런스 상세 대응, 실제 3D 메시 생성, 임의 프로젝트 의미 보존 및 런타임 프리뷰 자동 발견을 완료로 주장하지 않는다. 이번에 연결한 세 보기는 구현했고, 세부 외형의 적합성은 실제 캡처 확인과 사용자 판단이 남아 있다.

디스크 여유가 확보되어 이전에 저장하지 못한 `design/references/preview-product-20261101/depth-ai-reference-14.zip`도 만들었다. 14장 모두 PNG 디코딩과 ZIP 내부 바이트 해시를 확인했다. 이는 생성 레퍼런스이며 앱 캡처가 아니다.
