# 프리뷰 전체 요소의 소스 연결과 공간 유지

## 사용자 거부와 수정 범위

사용자는 이전 46개 검사를 통과한 평면 구성판도 거부했다. 두 사진 외 텍스트를 선택할 수 없었고, 이미지 자체를 선택하면 사용처가 빠졌으며, 공간을 탐색하다 큰 PC 구성판으로 바뀌었다. 이전 검사 수는 이 요구의 충족이나 디자인 승인이 아니다.

이번 수정은 현재 source-mapped preview의 선택과 공간 표시를 바로잡는다. 임의 프로그램의 모든 화면 요소를 자동으로 발견하는 범용 런타임 어댑터, 실제 MR 헤드셋 런타임을 구현했다는 뜻은 아니다.

## 구현

- `PreviewSources.cs`가 실제 `depth.preview.json`의 제목·라벨·상품명·설명·가격·이미지·합계 정의를 정식 graph entity로 인덱싱한다. JSON 토큰 위치로 행과 파일 해시를 기록한다. 같은 문구가 두 곳에 있어도 서로 다른 ID와 정확한 위치를 유지한다. 이 ID와 관계를 UI와 AI 도구가 공유한다.
- 가격과 합계는 실제 값/계산 코드로 연결한다. 이미지는 에셋 ID와 선언된 사용처를 함께 추적한다. view-owner/view-binding/view-action/view-asset은 선언된 preview adapter 근거이며 런타임 관찰이나 AI가 추측한 호출로 표시하지 않는다. View를 직접 열면 소유한 모든 요소를 포함하지만 개별 가격을 열 때 다른 상품의 무관한 가격까지 끌어오지 않는다.
- 프리뷰의 18개 텍스트·값·이미지 요소와 별도 실행 버튼을 선택할 수 있다. 선택 시 프리뷰는 왼쪽으로 이동하고, 무관한 모듈은 페이드아웃하며, 구성의 모든 ID가 같은 공간 카메라 안에서 함께 전진한다. 공간뷰에서 평면 구성판을 자동 표시하지 않는다. Workbench와 사용자가 요청한 코드 읽기는 별도 조작으로 유지한다.
- 실제 그래프의 스프링 배치와 충돌 분리로 관계가 있는 몸체를 모은다. 모든 소스 관계를 그리며 동일한 두 모듈 사이의 여러 참조 위치도 버리지 않는다. 호출은 파랑, 참조는 보라, 선언된 화면 연결은 청록이다. 구성 안의 몸체를 선택해도 기능 rootId와 전체 구성은 유지한다.
- 드래그 중에만 이동하고 휠로 확대한다. 작은 몸체는 이름·값·연결 수를 우선 표시한다. 확대할 때 600→1200 텍스처 해상도로 전환하고 상세 내용을 다시 표시한다. 속성 draft, 검토, 코드, 이미지 상세, 수준별 설명 진입을 보존한다.
- 자동 Meta 분석 완료 시 목록 팝업을 강제로 열지 않도록 했다. 사용자가 요청한 분석/목록 열기는 유지한다. 이 마지막 분기의 실제 Meta 응답은 이번에 재호출하지 않았으므로 실제 모델 회신 검증으로 확대하지 않는다.

최종 EXE의 `preview-product.0.image.png`, `group-1680.png`, `group-1280.png`를 직접 열어 확인했다. 이미지를 선택하면 15개 모듈과 20개 관계가 표시되며 독립 이미지 한 장으로 끝나지 않는다. 밝은 공간과 개별 유리 몸체를 유지한다. MR 구성 레퍼런스 `design/references/mr-workspace-20261030/03-feature-composition.png`와도 비교했다. 사용자의 시각적 최종 승인은 없으며 실제 MR 환경의 재현/기기 실행과 구분한다.

전환 영상/프레임 리뷰는 `artifacts/unity-live-20261031-220626/motion-review.mp4`, `motion-review.html`이다. 3개 전환의 26개 캡처를 약 10fps 표본으로 묶었으며 실시간 성능 영상이 아니다.

실패 기록도 보존한다. `214828`과 `214903`은 연결선 수 불일치로 실패했고 이후 선택 구성의 관계만 사용하며 반복 참조를 버리던 중복 제거를 없앴다. `215015`의 111개 통과는 지나치게 반듯한 격자 배치를 검토한 중간 결과다. `215537`의 116개 이후 작은 창의 요약 표시를 추가했다. 첫 EXE `220211`은 숨긴 창 때문에 대부분 검은 캡처가 나와 화면 검증으로 인정하지 않았다. 창을 표시한 `220545`와 최종 `220934`에서 다시 확인했다. 첫 실행의 자동 Meta 분석 여부는 별도로 입증하지 않았으므로 그 실행의 “No Meta call” 문구는 증거로 사용하지 않는다.

## 실행과 남은 경계

새 실행 파일은 `artifacts/windows-spatial/Depth AI.exe`다. 기존 `artifacts/windows/` EXE와 이전 소스/시안/캡처를 보존했다. 실행은 `powershell -ExecutionPolicy Bypass -File scripts/run-spatial.ps1`을 사용한다. 새 서비스와 빈 포트를 지정하고 저장소 `.env`를 참조하므로 키를 번들에 복사하지 않는다. `-ProjectPath`로 다른 프로젝트를 지정할 수 있지만 화면 선택 매핑에는 해당 프로젝트 어댑터가 필요하다.

현재 MetaAIHack Editor에도 `use-current-service` 고정 명령으로 `artifacts/service-spatial-bindings/Depth.Service.exe`와 포트 52691을 지정했다. 현재 Editor 프로세스에만 적용되며 재시작하면 사라진다. 일반 Release 출력은 과거 PID 39740의 잠금이 남아 있어 이 별도 빌드를 사용한다. MCP는 이번에도 WorldVR를 반환했으므로 그 프로젝트를 변경하지 않고 MetaAIHack의 프로젝트 로컬 검증 명령으로만 실행했다.

이번 작업은 새 Meta 품질/이미지 생성, GLB, MR 헤드셋, 모든 프로젝트의 자동 UI 추적이나 모든 기능의 100% 성공을 입증하지 않는다. 실제 모델 성공의 이전 기록은 `LIVE-VERIFICATION-2026-10-31.md`와 구분한다.
