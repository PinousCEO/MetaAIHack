## 최신: 큰 프리뷰에서 실제 코드와 전체 구성으로 이동

사용자가 큰 프리뷰와 프리뷰 요소를 눌러 구현 코드를 확인하는 흐름이 핵심이라고 지적했다. 이전 비교 화면의 작은 두 이미지는 선택 대상이 아니었고, 기존 서비스의 프리뷰 바인딩을 사용하지 않았다. 이 누락을 수정했다.

- 비교 화면의 파일 사이드바를 큰 프리뷰로 교체했다. 데스크톱에서 작업면 폭의 44%를 사용하고 Enlarge로 56%까지 넓힌다. 좁은 창에서는 프리뷰를 먼저 표시하는 세로 배치를 사용한다. 파일 목록은 접을 수 있다. 선택한 요소의 선언 위치, 직접 연결된 소스, 코드 발췌가 프리뷰 옆에 표시되고 전체 모듈/관계도 함께 남는다.
- `style-study/preview.js`는 실제 `BehaviorPreview.bindings` ID를 사용한다. 예제의 텍스트·값·이미지·버튼 19개 모두 클릭할 수 있다. 총액은 실제 CalculateTotal 본문과 Subtotal/DiscountPercent 소스를 즉시 보여 준다. 제목은 선언 문자열, 이미지는 선언 위치와 실제 에셋·사용처를 보여 준다. 코드 멤버로 이동해도 프리뷰 root와 전체 구성을 유지한다.
- EXE는 현재 서비스의 `/view`, `/graph`, `/composition`, `/source`, `/project-assets`를 직접 사용한다. HTML 단독 실행은 모든 바인딩 구성/소스/에셋을 내보낸 예제 스냅샷임을 표시한다. 기존 제품에서 비교 화면으로 이동하거나 돌아와도 현재 프로젝트를 유지한다. 임의 프로젝트의 런타임 UI를 자동으로 발견한 것이 아니다. 어댑터가 없으면 예제 화면을 대신 표시하지 않고 실제 소스 탐색을 제공한다.
- 빠른 연속 클릭의 이전 응답은 최신 선택을 덮어쓰지 않는다. 조회 실패는 기존 구성을 보존하며 오류를 표시한다. 빈 프로젝트에는 이전 예제 노드가 남지 않는다.
- 일반 앱도 시작 화면을 Composition으로 바꾸고 프리뷰 너비·글씨·이미지를 확대했다. Project preview의 **Large preview** 링크로 세 스타일을 사용하는 새 프리뷰 작업면을 연다. 기존 분리/통합/에셋/검토 기능은 일반 앱에 유지한다.

## 최신: 내부 겹침 수정

사용자는 글자·아이콘·UI가 겹친다고 지적했다. 이전 검사에서는 모듈 몸체의 겹침과 그래프 ID를 확인했지만, 내부 글자의 실제 높이와 아이콘 사이 간격을 확인하지 못했다. 큰 원인의 하나는 아이콘을 y=30~53에 두고 제목 기준선을 y=64에 둔 채 제목의 글자 높이를 고려하지 않은 고정 SVG 배치다. 같은 경로의 가장 긴 구간에 여러 관계 라벨을 쌓던 문제도 있었다. 이 설명은 코드 점검에 근거하며 새 실제 캡처 판독 결과가 아니다.

- 모듈 내용은 HTML grid/flex 흐름으로 배치한다. 아이콘과 이름은 분리된 칸, 역할과 값은 분리된 항목이다. 마름모/타원의 텍스트 영역은 실제 도형 안에 내접한다. 이름에 `wbr`을 넣어 식별자 원문을 바꾸지 않고 줄바꿈하며 전체 이름은 title/aria-label에도 남는다.
- 반복적인 관계 라벨은 선 위에 모두 띄우지 않는다. 선을 가리키거나 키보드로 접근하거나 선택하면 별도 설명 영역에 방향·종류·원본 위치를 표시한다. 모든 관계 ID와 근거는 보존한다.
- 메뉴·검색·통계·툴바가 좁은 영역에서 다음 줄로 배치된다. 파일 아이콘과 파일명은 각각의 칸에 배치하며, 1000px 이하에서는 작업면·설명·파일을 세로로 배치한다. 본래 세 스타일의 몸체와 색을 유지했다.
- 최신 172개 DOM·기하 검사: `artifacts/style-study-checks-1793528372893/report.json`. 도형 안 텍스트 영역, 식별자 원문, hover 근거와 기존 선택/소스/테마 동작을 검사했다. 별도 사각형 fixture 6개로 실측 검사기가 아이콘/제목 겹침, 잘린 제목, 역할/값 겹침, 패널 겹침을 거부하는지 확인했다. 모두 실제 픽셀과 구분한다.
- `layout-audit.js`는 실제 브라우저의 `getBoundingClientRect`, scroll/client 크기로 텍스트·아이콘·메뉴의 충돌을 확인한다. DOM 에뮬레이터의 크기 0은 검수 불가로 돌려준다. `--style-study-smoke`는 큰 창/두 테마 6장, 작은 창 3장, 작은 창의 125% 확대 3장으로 총 12장이다. 먼저 PNG를 저장하므로 겹침 검사가 실패해도 해당 화면이 남는다.
- 배포 폴더의 코드 일치를 `artifacts/style-study-spacing-check.json`에 기록한다. 직접 네이티브 실행은 다시 `spawn EPERM`이었으며 새 PNG는 없다. 사용자에게 `--style-study-smoke`를 요청했다. 브라우저에서는 Ctrl+R로 수정본을 볼 수 있다. **새 실측 검사 통과나 전체 시각 승인으로 기록하지 않는다.**

사용자는 설계 도감(2), 구조 노선도(4), 방사형 지도(5)를 마음에 들어 했지만, 기존 구현이 시안과 달라지는 문제를 지적하며 구현 가능성을 물었다. 세 보기를 유지할지 한 화면으로 합칠지 질문했고 아직 답은 없다. 기본값으로 세 가지 보기를 전환하는 읽기 전용 비교 화면을 만들었다. 기존 제품 기본 화면은 교체하지 않았다. 시각적 최종 승인이나 전체 제품 구현 완료가 아니다.

## 실제 구현

- `desktop/ui/style-study/index.html`: 독립 브라우저에서 파일을 열 수 있다. 배포 EXE의 `--style-study`도 같은 화면을 연다.
- `guide`: 밝은 종이색, 세리프 표제와 모듈명, 폴더 탭·겹침·절개 테두리, 소스 근거를 읽는 검사창이다. 정교한 래스터 종이 질감은 그대로 재현했다고 주장하지 않는다.
- `routes`: 각진 조정 모듈, 검증 마름모, 공유 구현의 이중 경계, 실선 호출과 점선 참조를 사용한다. 실제 대상 끝에만 화살촉을 붙인다.
- `orbit`: 선택 범위의 중심 모듈, 다른 호출자와 공유 대상, 원형 배치 가이드, 짙은 바탕·라임 강조·보라색 몸체를 사용한다. 거리에는 수학 지표 의미가 없다고 명시한다. 선택만으로 계속 몸체가 이동하지 않는다.
- 세 보기에서 같은 ID의 선택, 소스 발췌와 관계 근거를 유지한다. 각 보기의 테마 전환, 초보자/숙련자 구조 설명, 관계 클릭·키보드 선택, 파일별 선택, 검색 강조, 이동·확대·전체 보기, 소스 펼치기, 원본 레퍼런스 열기가 있다.
- 장식 이미지를 UI 배경으로 놓은 구현이 아니다. 모듈과 선은 실제 SVG/DOM이다. PNG는 프로젝트 에셋 썸네일과 명시적인 레퍼런스 비교 창에만 쓴다.
- 분리·통합·에셋·검토는 본제품에 있는 기능이며 이 비교 화면의 기능으로 재구현하지 않았다. 해당 상단 표기는 비활성 안내다. 새 Meta 호출도 없다.

## 데이터와 관계

`desktop/style-study-data.cjs`가 Checkout 복사본을 실제 .NET 서비스로 인덱싱했다. 전체 ApplyCoupon 구성 13개에 외부 직접 소비자 Estimate 1개를 추가한 **14개 요소, 19개 소스 발생 근거**다. 원본 인수 데이터는 `artifacts/style-study-1793522022902/export.json`, 표시 데이터는 `desktop/ui/style-study/data.js`다. 스냅샷임을 화면에 표시하며 임의 프로젝트 실시간 분석 결과로 주장하지 않는다.

같은 출발·도착·관계 종류는 선 하나로 묶되 모든 원본 관계 ID와 호출 위치를 보관한다. 지원 필드와 에셋도 하단에 실제 ID의 몸체로 표시한다. 현재 구조 설명은 이 스냅샷에서 계산한 사실과 기존 소스 메모이며 모델의 생성 당시 사고 기록이나 새 Meta 설명이 아니다.

기하 배치와 데이터는 `layout.js`로 분리했다. 노드 장애물을 피하는 격자 경로 탐색을 사용한다. 첫 검사에서 촘촘한 하단 요소의 옆 포트가 이웃 요소 안에 놓이는 문제를 발견해 하단 요소의 진입을 상단 열린 통로로 바꿨다. 카드 수를 줄이거나 데이터를 지워 통과시키지 않았다.
