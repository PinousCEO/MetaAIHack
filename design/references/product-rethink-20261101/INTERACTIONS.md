# 8개 화면의 조작 설계

이 문서는 이미지의 의도를 설명한다. 현재 Electron 클라이언트에 모두 구현됐다는 뜻이 아니다.

| 화면 | 주 조작 | 바뀌는 것 | 유지할 것 |
|---|---|---|---|
| 전체 지도 | 프로젝트 열기 → 역할별 묶음 선택 → Meta 분석 | 분석 대상과 모듈 설명 | 실제 소스 ID, 공유 구현의 단일 소유, 분석 전/후 상태 |
| 전체 구성 | 프리뷰 요소 선택 → 모듈 검사 → 내부 펼침 | 구성 root는 명시적 펼침에서만 변경, 검사 대상은 독립 변경 | 형제 모듈, 실제 관계, 소스/에셋 출처, 돌아갈 위치 |
| 이해 | 모듈 열기 → 개념/근거 읽기 → 수준 전환 → 질문 | 설명 분량과 학습 그림 | 같은 근거·불확실성, 기존 설명 재사용, 소스 기반 해석/생성 당시 기록 구분 |
| 관계 | 관계 종류 선택 → 경계/행렬 → 변경 영향 | 강조선, 선택 지표와 영향 범위 | 방향과 가중치 뜻, 정적/관찰/추정 출처, 사이클 보존 |
| 분리 | 기능 선택 → 목적지/지시 → Meta 제안 → 파일 비교 | 검토할 replace/create/delete 제안 | 승인 전 원본, 공개 계약과 호출 근거 |
| 통합 | 원본/대상 선택 → 계약 비교 → 재사용 판단 → 제안 | 통합 후보와 변경 파일 | 원본 프로젝트 보존, 후보를 호환성 증명으로 취급하지 않기 |
| 에셋 | PNG 스타일/프롬프트 → 생성 → 검토 → 가져오기 | staging 에셋과 승인된 목적지 | 생성 출처와 파일 해시, 기존 에셋 보호, 메시/PNG 구분 |
| 검토 | 구조/코드 차이 → 복사본 검증 → 승인 → 이력/undo | 제안 상태, 검증 결과와 원본 적용 | 프로젝트/revision/해시 일치, 필수 검사 차단, 되돌리기 별도 검토 |

## 그래픽을 실제 UI로 옮길 때

- 모듈 몸체는 역할색과 작은 소켓, 읽는 면과 내부 영역으로 구성한다. 펼침은 내부 선언을 같은 몸체의 하위 구조로 드러내는 동작이다. 옆면은 얕은 깊이 표현이며 텍스트를 기울이거나 카메라 원근에 종속시키지 않는다.
- 미선택 몸체도 읽을 수 있게 남긴다. 선택선은 대비를 올리되 그래프의 다른 모듈을 없애지 않는다. 연결은 반드시 소스 관계의 ID와 근거를 가진다.
- 실제 의존선, 포함 경계, 제안 매핑 점선, 개념 설명의 항목 흐름을 서로 다른 범례로 표현한다. 같은 화살표 스타일에 서로 반대 의미를 섞지 않는다.
- 작은 창에서는 긴 텍스트를 일괄 축소하지 않고 검사창 접기, 작업면 확대와 검색을 제공한다. 모듈 이름/코드/근거는 별도 읽는 면에서 원문으로 접근한다.
- 애니메이션은 선택·펼침·파일 이동·검토 상태의 전이를 설명한다. 자동 부유나 임의 카메라 이동은 요구하지 않는다. 모션 줄이기를 지원하고 이동 중 클릭 대상이 튀지 않게 한다.
- 분석/생성 중, 연결 실패, 미해석 관계, 오래된 설명, 생성 실패, 검증 미실행/실패/만료, 빈 프로젝트를 각각 실제 상태로 표시해야 한다. 이미지의 대표 화면은 이 모든 상태를 동시에 그린 것이 아니다.
- 사이드바 픽토그램과 워드마크의 세부 모양은 생성 이미지 사이에 변형이 있다. 구현 시 하나의 벡터 아이콘 체계로 통일한다. 이는 기존 레퍼런스를 재사용하라는 뜻이 아니다.
