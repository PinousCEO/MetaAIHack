# Depth AI — 프리뷰 중심 전체 기능 레퍼런스 14장

이번 요청은 “지금까지 말한 모든 내용을 담은 레퍼런스 이미지 10장 이상”이다. 일반 Windows EXE 방향을 유지해 14개 화면으로 구성한다. **제품 화면의 시각 검수를 대신한 결과가 아니며**, 실제 EXE 캡처·Meta 응답·기능 완료 증거가 아니다. 이미지 생성기는 built-in image_gen이다. 제품 내 AI 공급자로 설계한 Meta와 디자인 이미지 생성 도구를 구분한다.

## 핵심 조작

큰 프로젝트 프리뷰에서 텍스트, 값, 이미지, 버튼을 선택한다. 선택 요소의 선언 위치·직접 연결 소스·전체 기능 구성이 함께 나타난다. 관련 모듈을 한 개씩 교체하며 보여 주지 않는다. 모듈 내부를 읽거나 스타일을 바꿔도 프리뷰 선택과 구성 root를 유지한다. 무관한 프로젝트 배경만 흐려지고, 선택 기능을 이루는 모든 멤버는 남는다.

## 공통 시각 규칙

- 영어 UI, DEPTH AI 워드마크, 프로젝트 선택, Explore / Explain / Split / Merge / Assets / Review 내비게이션.
- Field Guide의 읽기 면, Route Atlas의 관계 문법, Orbit의 집중 배치를 같은 제품 안의 보기로 사용한다.
- 아이보리 외곽과 다크 네이비 테마, 인디고 선택색, 로직의 폴더 형태·상태 캡슐·검증 게이트·에셋 프레임을 공통으로 쓴다.
- 전체 지도가 있을 때도 프리뷰를 작은 썸네일로 축소하지 않는다. 변환/수학/에셋 전용 화면은 해당 작업의 큰 도면·제작 면을 사용한다.
- 선은 글자와 겹치지 않고 모듈 경계에서 끝난다. 실제 호출, 참조, 선언된 바인딩, 파일 이동 매핑을 같은 의미로 쓰지 않는다.
- 공간 이동은 일반 데스크톱 캔버스 조작이다. Unity·MR·헤드셋 UI를 되살리지 않는다. 3D는 에셋 작업 대상이다.
- 전환 목표는 “선택 강조 → 관련 구성 함께 모으기 → 소스 면 열기”이다. 글자와 아이콘을 몸체와 함께 계속 확대하지 않으며, 모션 줄이기 설정을 유지하는 구현이 필요하다. 정지 이미지는 애니메이션 구현 증거가 아니다.

## 현재 소스와 정확성

Checkout의 ApplyCoupon은 IsValid, CalculateTotal, SetTotal, Read를 호출한다. CalculateTotal은 DiscountPercent를 참조하며, 식은 `subtotal * (1 - DiscountPercent / 100)`이다. 120과 20% 예제의 결과는 96이다. Estimate의 소유 타입은 CartSummary이며 동일한 CalculateTotal을 재사용한다. CouponRules의 두 멤버는 DiscountPercent와 CalculateTotal이다. IsValid는 별도 CouponValidator에 있다.

TaskRunner의 App.cs에는 Program.Main과 Pricing.Total이 있다. JobQueue.cs는 pending, Add(string item), Next(), Count를 갖는다. Add는 Enqueue, Next는 Dequeue를 사용한다. 생성 초안이 추가한 가짜 멤버·프로젝트명·디렉터리·부정확한 호출선은 별도 교정 프롬프트에 기록한다.

가중치 calls=3, references=2, contains=0.5는 현재 수학 모델의 공학적 설정이다. 행렬 예시는 A=ApplyCoupon, B=CalculateTotal, D=DiscountPercent인 선택 부분 그래프이며 다른 모든 멤버를 뜻하지 않는다. Orbit의 시각적 거리는 수학적 중요도 점수가 아니다.

## 구현 상태와 구분

- 프리뷰는 선언된 소스 바인딩 기반이다. 임의 프로젝트의 실행 화면을 자동 발견·복원하거나 모든 언어를 의미 보존하며 분리하는 기능의 완료를 의미하지 않는다. 새로운 프로젝트의 지원 범위와 분석 결과를 먼저 확인해야 한다.
- 설명은 근거가 있는 설계 이유와 자료구조의 특성이다. 모델의 비공개 내부 사고과정을 표시하거나 작성자의 기록되지 않은 의도를 사실로 단정하지 않는다.
- 모듈 계약/코멘트는 사람이 읽는 설명과 AI용 문맥을 연결하는 디자인이다. 초기 프로젝트 인덱싱과 후속 선택 모듈의 문맥 읽기는 구분한다.
- 분리·통합·주석·에셋 가져오기는 제안/검토/검증/승인 단계가 보이도록 설계했다. 이미지의 샘플 상태를 실제 모델 실행 또는 승인 결과로 사용하지 않는다.
- 12번 실제 3D 메시 제작은 사용자 요구를 담은 **목표 워크플로**다. 현재 기본 생성 경로는 PNG이고 3D 스타일도 PNG이며, Meta API의 실제 GLB 메시 생성 연결을 완료했다고 주장하지 않는다. 필요한 메시 기능이 연결되기 전에는 생성/내보내기를 사용할 수 없는 상태로 구분한다.
- 래스터의 세부 글자·선·작은 경로 표현은 실행 가능한 코드나 정밀 배선 계약이 아니다. 정확한 소스/API와 위 대응 규칙이 후속 구현 기준이다. 사용자 최종 승인은 아직 없다.

## 최종 래스터 검토와 남은 차이

14장의 큰 영역 배치, 프리뷰 비중, 주요 제목·아이콘, 수준별 설명, 단계별 제안 상태를 직접 살폈다. 잘못 생성된 메서드 본문, FIFO 방향, 에셋과 로직의 가짜 호출, 3D 연결 완료처럼 보이는 표기를 교정했다. 이는 실제 앱 화면 검수나 픽셀 단위 무결성 보장이 아니다.

작은 선과 라벨에는 다음 차이가 남아 있어 구현 데이터로 옮기면 안 된다. 02의 CalculateTotal 아래 짧은 점선은 Total에 대한 직접 참조 근거가 아니다. 03과 14의 IsValid 소유 타입은 CouponValidator, Read 소유 타입은 TotalsView이며 view의 타입 표기도 TotalsView가 정확하다. 08의 두 번째 호출 몸체는 CartSummary 클래스 전체가 아니라 그 안의 Estimate 메서드를 뜻한다. 10의 Rewards import 매핑은 오른쪽 Rewards가 목적지이며 Program으로 이어지는 점선을 그대로 구현하지 않는다. 14의 일부 양끝 화살표는 생성 오차다. 실제 호출은 ApplyCoupon에서 IsValid·CalculateTotal·SetTotal·Read로, 참조는 CalculateTotal에서 DiscountPercent로 향한다. 01의 선택 호출 구성과 이 문서의 소스 규칙을 구현 기준으로 삼는다.

04는 전체 13개 구성 멤버를 읽기 쉽게 모은 소유·목록 화면이며 내부 호출선을 숨긴 상태다. 관계 전체 표시는 View connections에서 여는 설계다. 09·10·13의 파일 매핑 선과 호출 선은 서로 다른 의미다.

## 파일

- `index.html`: 14장 갤러리, 한 장씩 크게 보기와 원본 링크.
- `01-*.png`부터 `14-*.png`: 선택된 최종 이미지. 생성 원본은 기본 generated_images 위치에 보존하며, 디스크 부족 때 확인된 중복 사본만 제거했다.
- `depth-ai-reference-14.zip`: 14 PNGs, saved and hash-verified on 2026-11-02.
- `prompts.json`, `corrections.json`, `base-final-correction.json`, `fidelity-edits.json`, `selection-edits.json`, `source-owner-edits.json`, `final-scene-edits.json`, `final-selection-edits.json`: 실제 요청 프롬프트와 교정 기록.
- `image-manifest.json`: 최종 14장 목록. 기본 저장 중 디스크가 찬 7장은 도구 반환 PNG 데이터를 그대로 저장했다. 다시 그리거나 변환하지 않았다.
- `verification.json`: PNG and gallery checks. No runtime verification.
