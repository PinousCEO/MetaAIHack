# 같은 프로그램으로 보이게 만드는 기준

직전 8장의 기능 흐름은 유지하되 화면 사이의 시각적 불일치를 수정한다. 이번 입력은 사용자가 방금 검토한 product-rethink-20261101 시안이며, 그보다 오래된 레퍼런스는 사용하지 않는다.

## 고정 규칙

- 상단·왼쪽 메뉴·오른쪽 검사창·하단 도구의 위치와 크기를 고정한다. 로고는 장마다 다른 심벌을 생성하지 않도록 DEPTH AI 워드마크로 통일한다.
- 모듈은 같은 모서리, 4px 깊이, 테두리, 그림자, 포트를 공유한다. 큰 모듈을 펼쳐도 외곽 두께가 비례해서 커지지 않는다.
- 함수는 코랄, 상태는 민트, 타입·계약·뷰는 라벤더, 이미지 에셋은 샌드다. 신규/삭제/원본 프로젝트는 별도의 상태 칩으로 구분한다. 클래스인 Program/Pricing/Rewards를 출처에 따라 다른 역할색으로 바꾸지 않는다.
- 주요 버튼·선택은 인디고 하나로 통일한다. 로고, 아이콘 선 두께, 글자 위계와 간격도 동일하게 유지한다.
- 호출·참조·뷰 바인딩·포함·제안 매핑의 선 규칙을 나눈다. 출처나 기능마다 임의의 케이블 색을 추가하지 않는다.
- 머그와 화분은 같은 무광 클레이 스타일, 빛 방향, 배경과 형태를 반복한다. 프리뷰·썸네일·에셋 작업면에서 서로 다른 사진을 섞지 않는다.

## 제작 방식

기준 화면을 먼저 만든 뒤 built-in image_gen으로 나머지 화면을 맞췄다. 2·3·4번은 기준 화면과 기존 화면을 함께 입력했다. 이전 몸체 형태가 일부 남는 것을 확인해 5·6·7·8번은 기준 화면만 시각 입력으로 쓰고 기능 내용을 글로 지정했다. 마지막 국소 교정도 각 새 초안과 같은 기준 화면을 사용한다. `master-only-refinement.json`과 `consistency-corrections.json`에 실제 입력 전략과 교정을 기록했다. 원본 8장은 보존하고 별도 폴더에 저장한다.

설계 제안이며 현재 앱 화면이나 구현 완료, Meta API 실행 증거가 아니다. 최종 세부 픽셀·자산의 완전한 일치는 구현에서 공통 컴포넌트를 재사용해 보장해야 한다.

최종 3번은 기준 화면만 사용해 다시 생성한 뒤 Queue의 입력/출력·Count·설명 수준을 교정했다. 패널 폭도 기준 화면에 맞췄다. `final-polish.json`과 `queue-content-correction.json`에 이 과정을 기록했다.

2번은 전체 구성의 배치 시안이며 점선에 추가 화살촉이 남아 있다. 정확한 CalculateTotal → DiscountPercent 방향은 4번과 실제 소스 관계를 따른다. 이미지의 선을 그대로 데이터 계약으로 구현하지 않는다. 나머지 시각 검토 범위와 생성물의 한계는 `verification.json`을 참고한다.
