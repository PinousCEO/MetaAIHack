# 네 영역 고정 배치 — 사용자 수정 반영

2026-11-02 · [라이트·다크 갤러리](index.html)

사용자가 이전 12장의 배치가 요구와 다르다고 명확히 지적했다. 기존 디자인을 승인으로 취급하지 않는다. 이번 작업은 새 배치의 라이트/다크 기본 화면 2장을 생성한 것이며 EXE를 수정한 작업이 아니다.

## 사용자가 지정한 배치

| 위치 | 상시 유지할 영역 |
| --- | --- |
| 왼쪽 위 | 큰 프로젝트 프리뷰 |
| 왼쪽 아래 | 콘솔 및 CLI 채팅창 |
| 오른쪽 위 | 모듈 구성과 연결 작업면 |
| 오른쪽 아래 | 하이어라키, 모듈 검색과 빠른 탐색 |

콘솔과 CLI 대화·입력을 함께 보여준다. 하이어라키는 모듈을 빠르게 찾고 전환할 수 있는 독립 영역이다. 이 두 영역을 없애고 설명이나 소스를 전체 너비 하단에 배치하는 이전 구조는 채택하지 않는다. 자세한 소스·설명·분리·통합 작업을 추가하더라도 네 기본 영역을 임의로 대체하지 않는다.

프리뷰에서 누른 대상과 모듈 선택, 하이어라키의 선택 강조가 연결되어야 한다. 다른 모듈을 탐색할 때 현재 프리뷰와 연결 맥락을 잃지 않게 한다. 각 영역의 크기는 조절 가능한 설계로 제안하지만, 사용자가 정확한 분할 비율을 확정한 것은 아니다. 이미지의 비율을 절대값으로 간주하지 않는다.

## 생성·검토

built-in image_gen으로 이전 이미지 입력 없이 새 기본 화면을 만들고, 그 결과를 편집해 라이트/다크 2장을 만들었다. 기본 프롬프트와 교정, 원본 경로는 prompts.json에 보존했다.

두 최종 이미지를 직접 확인했다. 큰 프리뷰/콘솔과 채팅/모듈/하이어라키가 동시에 보이고, 입력창·검색창·최근 모듈이 각각 지정 영역에 있다. 임의의 성공 로그와 가짜 인덱스 수를 제거하고 예시 대화임을 표시했다. 함수와 상태의 몸체도 구분했다.

남은 생성 오차:
- 라이트의 ApplyCoupon 선 시작점에 작은 추가 화살촉이 남았다. 실제 관계 방향은 ApplyCoupon → CalculateTotal이다.
- 다크에는 Estimate → CalculateTotal 연결이 누락됐다. 두 이미지를 정확한 관계 데이터나 누락 없는 전체 그래프의 증거로 쓰지 않는다.
- 라이트의 “all modules visible” 문구는 의도한 동작 설명이다. 예시 그림이 실제 전체 ID를 빠짐없이 표현한 것은 아니다. 구현은 서비스의 전체 구성 데이터를 사용해야 한다.
- localhost 주소, 대화 내용, 최근 선택 시간은 디자인 예시이며 실제 실행 세션이 아니다.
- 생성 이미지의 대비·클릭 영역·크기 조절을 실제 앱에서 검증한 것은 아니다.

이전 12장에 담긴 기능 요구는 유지하되, 후속 화면은 이번 사용자 지정 배치를 따른다. 연구 참고 자료는 ../perception-atlas-20261102/RESEARCH.md에 있다. 이번 작업에서 새 논문 검색이나 사용자 인지 실험을 수행하지 않았다.
