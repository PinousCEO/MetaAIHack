# 시각 인지 연구와 Depth AI 설계 판단

2026-11-02 · 새 레퍼런스 12장 · [갤러리](index.html)

이번 작업은 기존 레퍼런스 이미지를 입력으로 재사용하지 않은 새 디자인 탐색이다. 아래 연구의 발견과 이 프로젝트에 적용한 판단을 구분한다. 모든 사람에게 가장 빠르고 잘 보이는 UI라고 입증한 것은 아니다. 사람을 대상으로 한 비교 실험, 실제 앱의 접근성 검사, 시선 추적은 이번에 수행하지 않았다.

## 읽은 자료와 적용

### 1. 선택 대상을 찾는 시각적 주의

Healey & Enns, **Attention and Visual Memory in Visualization and Computer Graphics** (2012), IEEE TVCG 18(7), 1170–1188, DOI 10.1109/TVCG.2011.127. [논문 서지·초록](https://pubmed.ncbi.nlm.nih.gov/21788672/), [저자의 시각 인지 해설](https://www.csc2.ncsu.edu/faculty/healey/PP/).

논문의 초록·서지와 저자 해설을 확인했다. 논문 PDF 전체를 읽었다고 주장하지 않는다. 색·크기·방향 등 구별되는 시각적 특징은 대상을 찾는 데 도움이 될 수 있지만, 여러 특징의 조합과 주변 자극에 따라 탐색이 어려워진다. 어떤 특징을 어떤 정보에 배정할지에는 작업 맥락이 중요하다.

**이 프로젝트의 판단:** 선택한 프리뷰 요소와 관련 모듈에만 강한 주황색을 쓴다. 함수·상태·클래스·에셋은 색뿐 아니라 몸체 형태와 역할 단어로도 구별한다. 중요하지 않은 곳에 반복적인 강조색이나 장식을 추가하지 않는다. 이것이 최적의 팔레트라는 실험 결과는 아니다.

### 2. 연결선을 따라가는 비용

Ware, Purchase, Colpoys & McGill, **Cognitive Measurements of Graph Aesthetics** (2002). [저자 공개 논문 PDF](https://vislab-ccom.unh.edu/pdfs/GraphAesthetics.pdf).

공개 PDF의 문제 설정·실험 설명·논의를 확인했다. 연구의 최단 경로 탐색 과제에서는 경로의 연속성과 교차가 탐색 난도와 관련되었다. 특정 그래프에서 측정한 비용을 모든 코드 지도에 그대로 적용할 수는 없다.

**이 프로젝트의 판단:** 선을 글자 밖의 여백으로 보내고, 선택 경로를 연속적으로 추적할 수 있게 한다. 화살표 방향과 관계 종류를 명시하고 소속 경계와 호출선을 구분한다. 모든 선을 직각 또는 곡선으로 통일하면 언제나 좋다는 결론으로 확대하지 않는다. 생성 이미지의 선은 API 관계 데이터의 대체물이 아니다.

### 3. 전체 맥락과 상세 정보의 관계

Shneiderman, **The Eyes Have It: A Task by Data Type Taxonomy for Information Visualizations** (1996). [저자 공개 논문 PDF](https://www.cs.umd.edu/users/ben/papers/Shneiderman1996eyes.pdf).

공개 PDF의 분류와 작업 설명을 확인했다. 전체 개관, 확대·필터, 요청 시 상세를 보는 접근과 관계·이력·추출 작업을 다루는 설계 틀이다. 특정 UI 배치의 우월성을 증명한 사용자 실험은 아니다.

**이 프로젝트의 판단:** 큰 프리뷰를 선택해도 전체 구성 맥락을 유지한다. 클래스 경계 안에서 멤버를 펼치고 상세 소스와 설명은 별도 읽기 면에 둔다. 전체 지도를 먼저 볼 수 있으며 선택한 한 모듈만 남기고 나머지 구성을 잃어버리지 않게 한다.

### 4. 변화 과정의 이해와 애니메이션

Heer & Robertson, **Animated Transitions in Statistical Data Graphics** (2007). [공개 논문 PDF](https://sites.stat.columbia.edu/gelman/communication/HeerRobertson2007.pdf).

공개 PDF의 실험과 결론을 확인했다. 두 통제 실험의 통계 차트 과제에서 설계된 전환은 변화 이해를 도울 수 있었다. 효과는 전환 종류와 과제에 의존하며 복잡한 단계 분할이 항상 유리한 것은 아니다.

**이 프로젝트의 판단:** 선택 전후 모듈 위치와 식별성을 유지하고 필요한 변화만 짧게 보여주는 전환을 제안한다. 계속 흐르는 입자가 실제 실행이나 인과관계를 뜻하는 것처럼 보이지 않게 한다. 모션 줄이기를 제공해야 한다. 이번 12장은 정지 이미지이므로 애니메이션 구현·효과 검증의 증거가 아니다.

### 보조 자료: 혼잡도와 접근성

- Rosenholtz 등의 연구에 대응하는 MIT 공개 자료: [Feature Congestion and Subband Entropy measures of visual clutter](https://dspace.mit.edu/entities/publication/cbf48538-96a8-401c-a82a-2179ade7e6a8). 연구 소프트웨어 설명을 확인했다. 논문 전문 분석이나 이번 UI의 혼잡도 수치 계산을 수행하지 않았다. 반복 경계·라벨·강조를 줄이는 설계 검토의 참고로만 사용했다.
- W3C [Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): 색 이외의 단서도 제공한다. 역할 이름·형태·선택 외곽선을 병용한다.
- W3C [Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): 실제 구현에서는 일반 글자 4.5:1, 큰 글자 3:1 기준으로 측정한다. 생성 PNG 전체가 이 기준을 충족한다고 인증한 것은 아니다.

## 이미지에 반영한 설계 규칙

| 사용자가 알아내야 하는 것 | 표현 | 적용 장면 |
| --- | --- | --- |
| 내가 누른 것이 어디인가 | 큰 프리뷰, 선택 외곽선, 단일 강한 강조색 | 01–03 |
| 어떤 코드들이 함께 구성하는가 | 열린 클래스 경계, 서로 다른 함수·상태·에셋 몸체 | 01, 04, 05 |
| 왜 이런 구조를 썼는가 | 읽는 면과 구조 그림을 나란히 배치, 소스 근거 표시 | 05–07 |
| 어떤 방향으로 의존하는가 | 방향 있는 관계와 별도 행렬 발췌, 선택 영향 표시 | 08 |
| 무엇이 실제로 바뀌는가 | 원본/제안 파일, 계약과 목적지, 전후 코드 | 09, 10, 12 |
| 무엇이 생성·연결되었는가 | 큰 에셋 무대와 사용처, 미연결 기능의 상태 | 11 |

형태와 소속 경계를 쓰는 구체적인 조합은 이 프로젝트의 설계안이다. 위 논문이 이 조합을 직접 검증한 것은 아니다. 12장 전체의 일관성과 남은 생성 오차는 [검토 기록](DESIGN-NOTES.md)에 적었다.

## 후속 구현에서 검증할 과제 — 아직 실시하지 않음

1. 프리뷰의 총액·이미지·텍스트를 각각 선택하고 관련 파일과 모듈을 찾는다. 찾는 시간, 오답, 전체 구성 누락을 기록한다.
2. 같은 과제를 기존 화면과 새 구현에서 수행하되 순서를 교차 배정해 학습 효과를 줄인다.
3. 초보자는 FIFO의 사용 이유와 한계를, 숙련자는 계약·참조·변경 영향을 설명할 수 있는지 확인한다.
4. 라이트/다크, 작은 창, 125% 확대, 긴 식별자와 많은 모듈에서 잘림·겹침·탐색 오류를 측정한다.
5. 색을 구별하기 어려운 조건과 키보드 접근, 모션 줄이기를 실제 UI에서 검사한다. 갤러리의 회색조 보기만으로 접근성 검증을 대신하지 않는다.

이 검증은 정적인 생성 이미지를 실제 제품에 옮긴 뒤 필요한 작업이다. 이번 산출물은 연구를 참고한 디자인 제안이며 실제 EXE 완료나 기존 시안에 대한 사용자 승인으로 기록하지 않는다.
