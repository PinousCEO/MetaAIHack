# 사용자 조작형 도킹 작업공간

2026-11-02 · [레퍼런스 3장](index.html) · [조작 예제](prototype.html) · [생성 프롬프트](prompts.json)

## 최신 사용자 요구

사용자는 콘솔의 과도한 크기와 같은 크기의 네 영역 고정 배치를 거부했다. Unity 에디터처럼 인터페이스 위치와 크기를 사용자가 조작할 수 있어야 한다고 명시했다. 이전 “네 영역 고정” 해석은 폐기한다.

프리뷰를 크게, 모듈을 오른쪽 주 작업면으로 두고 콘솔은 얇은 하단 도크에서 시작한다. 하이어라키는 탐색 도구다. 이것은 기본 배치일 뿐 위치·크기를 고정하는 제약이 아니다. Console과 Meta CLI도 독립 패널이며 기본값에서 탭으로 묶을 수 있다.

## 레퍼런스

1. **01-compact-default.png**: 큰 프리뷰와 모듈 작업면, 짧은 Console / Meta CLI 하단 도크, 별도 높이의 하이어라키.
2. **02-drag-to-dock.png**: CLI 탭을 꺼내 오른쪽으로 끌 때 나타나는 도킹 위치 안내.
3. **03-user-layout.png**: CLI를 오른쪽 독립 열에 두고 콘솔을 탭 높이로 접은 사용자 배치.

built-in image_gen으로 새 기본 화면을 생성하고 이번 기본 화면만 후속 상태에 사용했다. 기존의 고정 4분할 이미지는 입력으로 사용하지 않았다. 선택된 최종 3장을 직접 보며 검토했고 잘못된 메서드 소속, 상수 표기, 파일명, 생성된 CLI 명령과 코드 발췌를 교정했다.

이 PNG는 디자인 이미지다. 실제 도킹 동작을 실행한 스크린샷이나 Meta 결과가 아니다. 쇼핑 프리뷰의 결제·배송 폼은 생성된 예시이며 현재 Checkout 샘플의 구현을 그대로 캡처한 것이 아니다. 일부 최근 목록의 상수 역할 아이콘과 소유 경계에 닿는 화살표는 정확한 소스 그래프 명세로 사용하지 않는다. 사용자 지정 배치 장면은 선택 관련 모듈의 일부를 보여준다.

## 별도 조작 예제에서 구현한 것

prototype.html을 브라우저에서 열면 사용할 수 있다. 별도 설치나 서버가 필요 없는 로컬 HTML/CSS/JS 예제다. 실제 앱의 서비스, Meta API, 키, 프로젝트 파일 수정과 연결하지 않았다.

- 다섯 독립 패널: Preview, Modules, Hierarchy, Console, Meta CLI.
- 탭을 다른 패널 가장자리로 끌어 분할 도킹하거나 가운데로 끌어 탭으로 묶기.
- 작업공간 바깥쪽 가장자리로 끌어 전체 높이/폭의 패널을 추가하기.
- 구분선 드래그와 키보드 방향키로 크기 조절.
- ⋯ 메뉴로 위치 선택, 키보드로 이동, 패널을 작업영역 안에 띄우기.
- 떠 있는 그룹의 위치·크기 조절 및 다시 도킹.
- 접기·펼치기, 탭 더블클릭 최대화, Esc 복원, 닫기와 Panels에서 다시 열기.
- 자동 배치 저장, Save layout으로 별도 저장, 기본/CLI 오른쪽/프리뷰 집중 배치와 Reset.
- 도킹·닫기·재열기 동안 작성 중인 CLI 초안과 모듈 선택 유지.
- 라이트/다크 및 샘플 프리뷰 총액 → 모듈 → 하이어라키 선택 연결.

떠 있는 패널은 브라우저 작업영역 안에만 있다. 별도 OS 창이나 다중 모니터로 분리하는 기능은 구현하지 않았다. 저장 대상은 배치이며 대화 초안은 현재 페이지 세션에서 유지된다. 브라우저가 로컬 저장을 막으면 현재 세션에서만 사용할 수 있고 상태줄에 표시한다.

대화의 Send는 초안을 표시할 뿐 전송하지 않는다. 콘솔은 /help와 /clear만 처리하고 다른 입력을 셸에서 실행하지 않는다. 모듈·프리뷰는 제한된 샘플이다. 제품의 전체 분석·설명·분리·통합·에셋 기능을 이 예제가 구현한 것은 아니다.

## 검사 범위

`node design/references/dockable-workspace-20261102/prototype-check.cjs`의 **18개 검사**가 통과했다. 상세는 interaction-checks.json이다.

배치 트리의 빈 그룹 정리·패널 유실 방지, 반복 이동·저장 상태, 네 방향 도킹, 전체 작업공간 도킹, 입력된 드래그/포인터/키보드 이벤트, 떠 있는 패널 이동·크기, 접기·최대화·복귀, 초안 보존, 메뉴 이동과 저장 복원을 검사했다. DOM 검사는 좌표를 주입한 사례이며 실제 OS 포인터·브라우저 레이아웃/픽셀 검사와 다르다.

기본 보안 설정의 Firefox headless 캡처도 시도했다. artifacts/docking-reference-browser-20261102/attempt.json은 captured:false, exited:false다. 45초 안에 PNG가 생성되지 않아 해당 시도의 프로세스를 종료했다. 보안 설정은 낮추지 않았다. 따라서 실제 브라우저 화면 검수를 통과했다고 기록하지 않는다.

이번 변경은 design/references 아래 레퍼런스와 별도 조작 예제, 작업 지침이다. 배포 EXE나 desktop 앱 소스에 도킹을 통합한 작업이 아니다. 사용자 최종 시각적 승인도 아직 없다.
